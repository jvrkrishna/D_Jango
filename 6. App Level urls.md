# Django Project No. 0004 — Creating Multiple Apps in One Django Project (Using `urls.py` Inside Each App)

## 🎯 Project Objective

In this project, we will improve **Django Project No. 0003 — HIETECH** by creating a separate `urls.py` file inside each Django application.

In this project, we will learn how to:

- Create a Django project
- Create multiple Django applications inside one project
- Register multiple applications in `settings.py`
- Create views in different applications
- Create a separate `urls.py` inside each application
- Connect application-level URLs with application views
- Use `include()` in the project-level `urls.py`
- Connect multiple application URLs with different URL prefixes
- Run and test all application URLs
- Understand the difference between project-level and application-level URL configuration

The Django project name is **HIETECH**.

The applications are:

```text
Students
Fees
Courses
```

The final URLs are:

```text
/students/view1/
/students/view2/

/fees/

/courses/
```

---

# 🔄 Improvement from Project No. 0003

In **Project No. 0003**, all URLs were written directly inside:

```text
HIETECH/urls.py
```

For example:

```python
path('students/view1/', v1.student_view1),
path('students/view2/', v1.student_view2),
path('fees/', v2.fees_view),
path('courses/', v3.course_view),
```

In **Project No. 0004**, each application gets its own `urls.py`.

```text
Students/
    views.py
    urls.py

Fees/
    views.py
    urls.py

Courses/
    views.py
    urls.py
```

The project-level `HIETECH/urls.py` uses `include()` to connect each application.

```python
path('students/', include('Students.urls')),
path('fees/', include('Fees.urls')),
path('courses/', include('Courses.urls')),
```

This makes the project cleaner and easier to maintain.

# 📌 Step 6: Create `urls.py` Inside Each Application

This is the main improvement in Project No. 0004.

Django does not automatically create `urls.py` when we create an application.

We create it manually.

Create:

```text

Fees/urls.py
Courses/urls.py
```

The structure becomes:

```text
Students/
    views.py
    urls.py

Fees/
    views.py
    urls.py

Courses/
    views.py
    urls.py
```

Each application now manages its own URLs.

# 📌 Step 7: Configure `Students/urls.py`

Create:

```text
Students/urls.py
```

Add:

```python
from django.urls import path
from . import views


urlpatterns = [
    path(
        'view1/',
        views.student_view1,
        name='student_view1'
    ),

    path(
        'view2/',
        views.student_view2,
        name='student_view2'
    ),
]
```

---

## 🔑 Understanding the Students URL Configuration

This line:

```python
from django.urls import path
```

imports the Django `path()` function.

This line:

```python
from . import views
```

imports the `views.py` file from the current application.

Here:

```text
.
```

means the current application directory.

Therefore:

```python
from . import views
```

refers to:

```text
Students/views.py
```

# 📌 Step 10: Configure Project-Level `urls.py`

Now open:

```text
HIETECH/urls.py
```

Import `include`:

```python
from django.urls import path, include
```

Complete code:

```python
from django.contrib import admin
from django.urls import path, include


urlpatterns = [
    path('admin/', admin.site.urls),

    # Include application-level URLs
    path('students/', include('Students.urls')),
    path('fees/', include('Fees.urls')),
    path('courses/', include('Courses.urls')),
]
```

---

# 🔑 Understanding `include()`

The following:

```python
path('students/', include('Students.urls'))
```

means:

> Send URLs beginning with `students/` to `Students/urls.py`.

Similarly:

```python
path('fees/', include('Fees.urls'))
```

sends URLs beginning with `fees/` to:

```text
Fees/urls.py
```

And:

```python
path('courses/', include('Courses.urls'))
```

sends URLs beginning with `courses/` to:

```text
Courses/urls.py
```

# ✅ Advantages of Application-Level URLs

## 1. Each App Is Self-Contained

The Students app manages its own:

```text
Students/views.py
Students/urls.py
```

The Fees app manages:

```text
Fees/views.py
Fees/urls.py
```

The Courses app manages:

```text
Courses/views.py
Courses/urls.py
```

---

## 2. Cleaner Project-Level `urls.py`

Instead of writing every individual view URL inside:

```text
HIETECH/urls.py
```

we only include the applications:

```python
path('students/', include('Students.urls')),
path('fees/', include('Fees.urls')),
path('courses/', include('Courses.urls')),
```

---

## 3. Easier to Maintain

If we want to add another Students URL, we modify:

```text
Students/urls.py
```

For example:

```python
path('profile/', views.student_profile, name='student_profile')
```

We do not need to modify the project-level URL configuration.

---

## 4. Easier to Add More URLs

Suppose Students later has:

```text
/students/view1/
/students/view2/
/students/profile/
/students/details/
/students/list/
```

All these URLs can be maintained inside:

```text
Students/urls.py
```

---

## 5. Better for Large Projects

As the number of applications and URLs increases, separating URL configurations prevents:

```text
HIETECH/urls.py
```

from becoming too large.

# 🧠 Important Concepts

## Project-Level URL

```text
HIETECH/urls.py
```

Its main responsibility is to connect the project with different applications.

Example:

```python
path('students/', include('Students.urls'))
```

---

## Application-Level URL

```text
Students/urls.py
```

Its main responsibility is to connect URLs with views inside the Students application.

Example:

```python
path('view1/', views.student_view1)
```

# ⭐ Key Points to Remember

```text
HIETECH/urls.py
```

➡ Project-level URL configuration.

```text
Students/urls.py
```

➡ Application-level URL configuration.

```python
from . import views
```

➡ Imports the current application's `views.py`.

```python
urlpatterns = [
]
```

➡ Contains the URL patterns for the application.

```python
path('view1/', views.student_view1)
```

➡ Connects `view1/` to `student_view1`.

```python
name='student_view1'
```

➡ Gives the URL a reusable name.

```python
include('Students.urls')
```

➡ Connects the project-level URL configuration to the Students application's URL configuration.

# 🧠 Most Important Difference

## Project-Level `urls.py`

```text

```

Think:

Example:

```python

```

## Application-Level `urls.py`

```text
Students/urls.py
```

Think:

> **Which view inside this application should handle this request?**

Example:

```python

```

# 🎯 Final Concept

The complete URL structure is:

```text
Project
   ↓
HIETECH/urls.py
   ↓
include()
   ↓
Application
   ↓
Students/urls.py
   ↓
path()
   ↓
Students/views.py
   ↓
View Function
```

Therefore:

> **Project-level `urls.py` → chooses the application.**

> **Application-level `urls.py` → chooses the view.**

This structure is cleaner, easier to maintain, and more scalable than keeping every application's URL patterns inside one project-level `urls.py`.
