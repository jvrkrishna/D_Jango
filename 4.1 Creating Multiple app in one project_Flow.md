# Django Project No. 0003 — HIETECH

## 🎯 Project Objective

In this project, we will learn how to:

- Create a Django project
- Create multiple Django applications
- Register multiple applications in `settings.py`
- Create view functions in different applications
- Import views from multiple applications
- Use aliases while importing views
- Connect URLs with different applications
- Run and test multiple application URLs

The Django project name will be **HIETECH**.

The applications will be:

```text
Students
Fees
Courses
```

We will create the following URLs:

```text
/students/view1/
/students/view2/
/fees/
/courses/
```

Each URL will execute a different view function.

### What is a Multiple-App Django Project?

A Django project can contain multiple applications.

In our example:

```text
HIETECH
   ↓
Project
   ↓
 ┌───────────┬───────────┬───────────┐
 ↓           ↓           ↓
Students    Fees       Courses
 ↓           ↓           ↓
Application Application Application
```

Each application can handle a different functionality.

For example:

```text
Students → Student-related functionality

Fees → Fee-related functionality

Courses → Course-related functionality
```

# What is a View?

A **view** is a Python function that receives an HTTP request and returns an HTTP response.

For example:

```python
def student_view1(request):
    return HttpResponse('<h1>Hello, you are in the Students section (view1)</h1>')
```

The basic flow is:

```text
Browser

   ↓

HTTP Request

   ↓

View Function

   ↓

HTTP Response

   ↓

Browser
```

# What is URL Routing?

URL routing connects a URL with a view function.

For example:

```python
path('students/view1/', v1.student_view1)
```

means:

```text
URL

   ↓

students/view1/

   ↓

student_view1()

   ↓

HTTP Response
```

Similarly:

```python
path('students/view2/', v1.student_view2)
```

means:

```text
URL

   ↓

students/view2/

   ↓

student_view2()

   ↓

HTTP Response
```

For Fees:

```python
path('fees/', v2.fees_view)
```

means:

```text
URL

   ↓

fees/

   ↓

fees_view()

   ↓

HTTP Response
```

For Courses:

```python
path('courses/', v3.course_view)
```

means:

```text
URL

   ↓

courses/

   ↓

course_view()

   ↓

HTTP Response
```

# 🔑 Why Do We Use `v1`, `v2`, and `v3`?

Each Django application has its own `views.py`.

We have:

```text
Students/views.py
Fees/views.py
Courses/views.py
```

Therefore, we import them using aliases:

```python
from Students import views as v1
from Fees import views as v2
from Courses import views as v3
```

Now we can use:

```text
v1 → Students views

v2 → Fees views

v3 → Courses views
```

For example:

```python
v1.student_view1
v1.student_view2

v2.fees_view

v3.course_view
```

This makes it clear which application the view belongs to.
