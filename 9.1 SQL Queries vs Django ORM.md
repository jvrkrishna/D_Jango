# SQL Queries vs Django ORM

## 1. Django Models

Let's use a simple **College Management** example.

```python
from django.db import models


class Department(models.Model):
    name = models.CharField(max_length=100)

    def __str__(self):
        return self.name


class Student(models.Model):
    name = models.CharField(max_length=100)
    age = models.IntegerField()
    city = models.CharField(max_length=100)
    marks = models.IntegerField()
    department = models.ForeignKey(
        Department,
        on_delete=models.CASCADE,
        related_name="students"
    )

    def __str__(self):
        return self.name
```

# 2. SELECT — Get All Students


# 3. WHERE — Filter Students

Get students whose age is greater than 20.

### SQL

```sql
SELECT *
FROM student
WHERE age > 20;
```

### Django ORM

```python
Student.objects.filter(age__gt=20)
```

### Common Django ORM Comparison Operators

| SQL  | Django ORM  |
| ---- | ----------- |
| `>`  | `__gt`      |
| `>=` | `__gte`     |
| `<`  | `__lt`      |
| `<=` | `__lte`     |
| `=`  | `=`         |
| `!=` | `exclude()` |

### Example

```python
Student.objects.filter(age__gte=20)
```

# 13. MAX / MIN / AVG

## Maximum Marks

### SQL

```sql
SELECT MAX(marks)
FROM student;
```

### Django ORM

```python
from django.db.models import Max

Student.objects.aggregate(Max("marks"))
```

## Average Marks

### SQL

```sql
SELECT AVG(marks)
FROM student;
```

### Django ORM

```python
from django.db.models import Avg

Student.objects.aggregate(Avg("marks"))
```

## Other Aggregate Functions

```python

    Count("id"),
    Sum("marks"),
    Max("marks"),
    Min("marks")
)
```

# 15. JOIN

Our models have this relationship:

```text
Student
   |
   | ForeignKey
   ↓
Department
```

Get student name and department name.

### SQL

```sql
SELECT student.name, department.name
FROM student
JOIN department
ON student.department_id = department.id;
```

### Django ORM

```python
Student.objects.select_related("department")
```

Then:

```python
for student in Student.objects.select_related("department"):
    print(student.name, student.department.name)
```

# 16. Filter Using a Foreign Key

Get students from the Computer Science department.

### SQL

```sql
SELECT student.*
FROM student
JOIN department
ON student.department_id = department.id
WHERE department.name = 'Computer Science';
```

### Django ORM

```python
Student.objects.filter(
    department__name="Computer Science"
)
```

## Important

The Django ORM uses `__` to traverse relationships.

```python
Student.objects.filter(department__name="Computer Science")
```

Meaning:

```text
Student → Department → name
```

# 20. SQL vs Django ORM — Quick Reference

| Requirement      | SQL                     | Django ORM                                  |
| ---------------- | ----------------------- | ------------------------------------------- |
| Get all records  | `SELECT * FROM student` | `Student.objects.all()`                     |
| Filter           | `WHERE age > 20`        | `.filter(age__gt=20)`                       |
| Not equal        | `WHERE city != 'Delhi'` | `.exclude(city="Delhi")`                    |
| AND              | `WHERE a=1 AND b=2`     | `.filter(a=1, b=2)`                         |
| OR               | `WHERE a=1 OR b=2`      | `Q(a=1) \| Q(b=2)`                          |
| Specific columns | `SELECT name`           | `.values("name")`                           |
| Sort ASC         | `ORDER BY marks`        | `.order_by("marks")`                        |
| Sort DESC        | `ORDER BY marks DESC`   | `.order_by("-marks")`                       |
| Limit            | `LIMIT 5`               | `[:5]`                                      |
| Count            | `COUNT(*)`              | `.count()`                                  |
| Max              | `MAX(marks)`            | `.aggregate(Max("marks"))`                  |
| Average          | `AVG(marks)`            | `.aggregate(Avg("marks"))`                  |
| Group By         | `GROUP BY city`         | `.values("city").annotate(...)`             |
| Insert           | `INSERT`                | `.create()`                                 |
| Update           | `UPDATE`                | `.update()`                                 |
| Delete           | `DELETE`                | `.delete()`                                 |
| Join             | `JOIN`                  | `.select_related()` / `.prefetch_related()` |

# 21. Important Concept

Django ORM does **not** eliminate SQL.

When you write:

```python
Student.objects.filter(age__gt=18)
```

Django generates SQL behind the scenes similar to:

```sql
SELECT ...
FROM student
WHERE age > 18;
```

The flow is:

```text
Python Code
     ↓
Django ORM
     ↓
SQL Query
     ↓
Database
     ↓
Result
```

# 22. SQL vs Django ORM — Advantages

## Django ORM Advantages

* Easier to write for Python/Django developers
* Works directly with Django models
* Usually more database-independent
* Helps reduce repetitive SQL
* Query parameters are handled safely in normal ORM usage
* Easy integration with Django relationships
* Good for most CRUD operations

## SQL Advantages

* Full control over the query
* Excellent for complex queries
* Useful for database-specific features
* Useful for advanced optimization
* Easier when you already have complex SQL
* Useful for advanced database features such as CTEs and window functions

---

# 23. When Should You Use Django ORM?

Use Django ORM by default for normal Django application development.

Examples:

```python
Student.objects.all()

Student.objects.filter(age__gt=18)

Student.objects.get(id=1)

Student.objects.create(...)

Student.objects.filter(id=1).update(...)

Student.objects.filter(id=1).delete()
```

---

# 24. When Should You Use Raw SQL?

Raw SQL can be useful when:

* The query is very complex
* The ORM query becomes difficult to understand
* You need database-specific functionality
* You need very fine-grained control over SQL
* An existing SQL query needs to be reused

Example:

```python
Student.objects.raw(
    "SELECT * FROM student WHERE age > %s",
    [18]
)
```

Always use parameterized queries rather than constructing SQL with string interpolation.

# 26. Interview Answer

If asked:

**"What is the difference between SQL and Django ORM?"**

You can answer:

> SQL is a database query language used to directly query relational databases, whereas Django ORM is a Python-based abstraction layer that allows us to interact with database tables through Django models. Django ORM generates SQL behind the scenes, making database operations easier and generally more database-independent. Raw SQL is useful when we need complex or database-specific operations that are difficult to express using the ORM.
