# PART A — UNDERSTANDING DJANGO

# 1. What Is Django?

Django is a:

> **High-level Python web framework used to build web applications quickly and securely.**

Django is written in Python.

Our technology stack is:

```text
Python
   ↓
Django
   ↓
CampusQuest
   ↓
Web Application / REST API
```

---

# 2. What Is a Web Framework?

Before Django, imagine we build a website completely from scratch.

We would need to handle:

```text
URL routing
HTML responses
Database communication
User authentication
Forms
Security
Sessions
Admin interface
Application structure
```

That is a lot of work.

A framework provides ready-made tools and conventions.

```text
Without Framework

Python
   ↓
Build everything yourself
   ↓
Lots of code
   ↓
More complexity


With Django

Python
   ↓
Django
   ↓
Ready-made web development tools
   ↓
Faster development
```

---

# 3. Why Django?

Django provides many features out of the box.

Important features include:

- URL routing
- Views
- Templates
- ORM
- Models
- Forms
- Authentication
- Sessions
- Admin panel
- Security features
- Middleware
- Static files support
- Database integration
- Application structure
- REST API support through Django REST Framework

---

# 4. Django Is Batteries-Included

You will often hear:

> **Django is a batteries-included framework.**

This means Django provides many commonly required web-development features instead of forcing developers to build everything from scratch.

For example:

```text
Django
├── URL routing
├── Views
├── Templates
├── ORM
├── Authentication
├── Admin
├── Forms
├── Sessions
├── Security
└── Middleware
```

---

# 5. Django's General Architecture

Django is commonly explained using:

> **MVT — Model, View, Template**

```text
              USER
               |
               v
              URL
               |
               v
              VIEW
             /    \
            /      \
           v        v
        MODEL    TEMPLATE
           |        |
           v        v
```

We will learn MVT in detail in later days.

For Day 3, remember:

```text
Model    → Data / Database
View     → Business logic
Template → User interface
```

# 6. Django Project vs Django Application

This is one of the most important concepts.


```text

├── leaderboard

└── core
```

Think:

```text

Apps
   ↓
Accounts
Challenges
Leaderboard
Notifications
```

# 39. `asgi.py`

File:

```text
config/asgi.py
```

ASGI means:

> **Asynchronous Server Gateway Interface**

It is the modern interface for asynchronous Python web applications.

Conceptually:

```text
ASGI Server
    ↓
ASGI
    ↓
Django
```

It is useful for asynchronous capabilities and protocols supported by ASGI-based systems.

For Day 3:

> Understand the purpose; don't worry about the internal implementation.

---

# 40. WSGI vs ASGI

| WSGI | ASGI |
|---|---|
| Older Python web-server interface | Modern Python web-server interface |
| Primarily synchronous | Supports asynchronous applications |
| Common in traditional Django deployments | Useful for async Django |
| `wsgi.py` | `asgi.py` |

Simple memory trick:

```text
WSGI → Traditional web interface
ASGI → Async-capable web interface
```

# 43. What Is `127.0.0.1`?

You will see:

```text
127.0.0.1
```

This is the loopback address.

It refers to:

> **Your own computer.**

Another common name is:

```text
localhost
```

So:

```text
127.0.0.1
```

and:

```text
localhost
```

commonly refer to your local machine.

---

# 44. What Is Port `8000`?

The complete development URL is:

```text
http://127.0.0.1:8000/
```

Here:

```text
127.0.0.1
```

means your computer.

```text
8000
```

is the port on which Django's development server is listening.

Think of a port as a numbered communication door.

```text
Computer
│
├── Port 80
├── Port 443
├── Port 3306
└── Port 8000 ← Django development server
```

MySQL commonly uses:

```text
3306
```

Django's development server commonly uses:

```text
8000
```

```cmd
python manage.py runserver 8001
```

Then open:

```text
http://127.0.0.1:8001/
```

---

## Error 4 — Django Check Error

Run:

```cmd
python manage.py check
```

Read the error carefully.

Do not immediately delete files or reinstall everything.

Django's error messages often tell you where the problem is.

# ⭐ 61. Day 3 Golden Rules

### Rule 1

A **project** is the overall Django website/application.

### Rule 2

An **app** provides a particular feature/functionality.

### Rule 3

`manage.py` manages the Django project through commands.

### Rule 4

`settings.py` controls project configuration.

### Rule 5

`urls.py` controls URL routing.

### Rule 6

`wsgi.py` provides the WSGI interface.

### Rule 7

`asgi.py` provides the ASGI interface.

### Rule 8

`127.0.0.1` means your local computer.

### Rule 9

`8000` is the default Django development-server port.

### Rule 10

The development server is for development/testing, not production deployment.
