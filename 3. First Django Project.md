# Step 1: Create a Django Project

```bash
django-admin startproject WelcomeProject
```

### What does this command do?

It creates a new Django project named **WelcomeProject**.

The basic structure will look approximately like this:

```text
WelcomeProject/
│
├── manage.py
│
└── WelcomeProject/
    ├── __init__.py
    ├── settings.py
    ├── urls.py
    ├── asgi.py
    └── wsgi.py
```

### Important files

| File | Purpose |
|---|---|
| `manage.py` | Used to perform Django project commands |
| `settings.py` | Contains project configuration |
| `urls.py` | Defines URL patterns |
| `asgi.py` | Used for ASGI deployment |
| `wsgi.py` | Used for WSGI deployment |
| `__init__.py` | Makes the folder a Python package |

### Simple way to remember

Think of a Django project as a **house**:

- `settings.py` → House settings
- `urls.py` → Directions/address system
- `views.py` → Person who decides what response to give
- `templates` → Pages shown to visitors
- `static` → Images, CSS, JavaScript, etc.

# Step 3A: Configure the Templates Folder

Open:

```text
WelcomeProject/WelcomeProject/settings.py
```

Find:

```python
TEMPLATES = [
    {
        ...
        'DIRS': [],
        ...
    },
]
```

Change:

```python
'DIRS': [],
```

to:

```python
'DIRS': [os.path.join(BASE_DIR, 'templates')],
```

### Why do we do this?

We are telling Django:

> **"Our HTML template files are located inside the `templates` folder."**

So when we write:

```python
return render(request, 't1.html')
```

Django knows where to look for `t1.html`.

### What is `BASE_DIR`?

`BASE_DIR` represents the main project directory.

Conceptually:

```text
BASE_DIR
   ↓
WelcomeProject/
   ├── templates/
   ├── static/
   └── manage.py
```

Therefore:

```python
os.path.join(BASE_DIR, 'templates')
```

means:

> Create the path to the `templates` folder inside the project directory.

### Important Note for Modern Django

Modern Django versions generally already provide `BASE_DIR` using `pathlib`, for example:

```python
BASE_DIR = Path(__file__).resolve().parent.parent
```

In that case, a simpler configuration is:

```python
'DIRS': [BASE_DIR / 'templates'],
```

We should use the form that matches the generated `settings.py`.

---

# Step 3B: Configure the Static Folder

At the bottom of `settings.py`, add:

```python
STATICFILES_DIRS = [
    os.path.join(BASE_DIR, 'static')
]
```

### Why?

We are telling Django:

> **"Our additional static files are inside the `static` folder."**

For example:

```text
static/
└── logo.png
```

Django can then find `logo.png`.

With modern `pathlib`-based settings, this can be written as:

```python
STATICFILES_DIRS = [
    BASE_DIR / 'static'
]
```

# `t1.html`

Start with:

```html
<b>Hello, {{name}}</b>
```

## What is `{{name}}`?

`{{ name }}` is a **Django template variable**.

Django will replace it with the value supplied by the view.

For example, if the view sends:

```python
{'name': 'John'}
```

then:

```html
<b>Hello, {{name}}</b>
```

becomes:

```html
<b>Hello, John</b>
```

So:

```text
{{name}}
   ↓
John
```

---

# Displaying Images

There are two approaches.

## Method 1: Using Django's `static` Template Tag

At the top of the HTML file:

```html
{% load static %}
```

Then:

```html
<img src="{% static 'logo.png' %}" alt="img not found">
```

### What does `{% load static %}` mean?

It tells Django:

> **"We want to use Django's static-file template features in this HTML file."**

Then:

```html
{% static 'logo.png' %}
```

asks Django to generate the appropriate URL for the static file.

This is the **recommended approach** for Django templates.

---

# Method 2: Direct Static URL

We can also write:

```html
<img src="/static/logo.png" alt="img not found">
```

This directly tells the browser:

> Look for `logo.png` inside `/static/`.

### Which method should we use?

We should use **Method 1 as the standard Django approach**:

```html
{% load static %}

<img src="{% static 'logo.png' %}" alt="img not found">
```

It is more flexible and is the normal pattern for Django templates.

# What is a View?

A **view** is a Python function that receives a request and returns a response.

Think of it like this:

```text
Browser
   ↓
Request
   ↓
View
   ↓
Response
   ↓
Browser
```

For example:

```python
def m1(request):
    return HttpResponse("Hello, John")
```

The view receives:

```python
request
```

and returns:

```text
Hello, John
```

---

# Process 1: Using `HttpResponse`

```python
from django.http import HttpResponse

def m1(request):
    return HttpResponse("Hello, John")
```

### Explanation

First:

```python
from django.http import HttpResponse
```

We import Django's `HttpResponse` class.

Then:

```python
def m1(request):
```

We create a view function called `m1`.

`request` contains information about the HTTP request sent by the browser.

Finally:

```python
return HttpResponse("Hello, John")
```

The server sends:

```text
Hello, John
```

back to the browser.

### Flow

```text
Browser
   |
   | HTTP Request
   ↓
m1(request)
   |
   | HttpResponse
   ↓
"Hello, John"
```

---

# Process 2: Using `render()`

Instead of directly returning text, we can return an HTML page.

```python
from django.shortcuts import render

def m1(request):
    return render(request, 't1.html', {'name': 'John'})
```

### What does `render()` do?

`render()` combines:

1. The HTTP request
2. An HTML template
3. Data for the template

Here:

```python
render(
    request,
    't1.html',
    {'name': 'John'}
)
```

means:

> "Open `t1.html`, give it the value `name = John`, and return the resulting HTML to the browser."

---

# Understanding the Dictionary

This part:

```python
{'name': 'John'}
```

is called **context data**.

It means:

```text
Template variable    Value
       ↓               ↓
     name            John
```

Therefore:

```html
{{ name }}
```

will display:

```text
John
```

So:

```html
<b>Hello, {{name}}</b>
```

will display:

**Hello, John**


---

# What is URL Routing?

URL routing tells Django:

> **"When a user visits this URL, which view function should execute?"**

The important line is:

```python
path('', m1)
```

Let's understand it:

```text
path('', m1)
     ↑   ↑
     |   |
     |   View function
     |
     URL path
```

The empty string:

```python
''
```

means the **root URL**.

Therefore:

```text
http://127.0.0.1:8000/
```

will call:

```python
m1(request)
```

---

# What about `extraurl`?

We can write:

```python
# path('extraurl/', m1)
```

If we remove the `#`:

```python
path('extraurl/', m1)
```

then visiting:

```text
http://127.0.0.1:8000/extraurl/
```

will call the same `m1` view.

So one view can be connected to different URLs.
