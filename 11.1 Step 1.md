```text
POST /student/
      |
      v
form.is_valid()
      |
      v
redirect("success")
      |
      v
/student/success/
```

This is the **Post/Redirect/Get (PRG)** pattern.

# 5. Create the Form

Open:

```text
students/forms.py
```

Add:

```python
from django import forms


class StudentForm(forms.Form):
    name = forms.CharField()
    dob = forms.DateField()
    gender = forms.ChoiceField(
        choices=[
            ("Male", "Male"),
            ("Female", "Female"),
            ("Others", "Others"),
        ]
    )
```

## What these fields do

### `CharField`

```python
name = forms.CharField()
```

Accepts text input.

### `DateField`

```python
dob = forms.DateField()
```

Accepts a date and validates that the submitted value can be interpreted as a date.

### `ChoiceField`

```python
gender = forms.ChoiceField(
    choices=[
        ("Male", "Male"),
        ("Female", "Female"),
        ("Others", "Others"),
    ]
)
```

Creates a field with predefined choices.

The first value is what Django stores in the submitted data, and the second value is what is displayed to the user.

For example:

```python
("Male", "Male")
```

means:

```text
Submitted value: Male
Displayed label: Male
```

# 6. Create the Views

Open:

```text
students/views.py
```

Use:

```python
from django.shortcuts import redirect, render

from .forms import StudentForm


def student_form(request):
    if request.method == "POST":
        form = StudentForm(request.POST)

        if form.is_valid():
            print(form.cleaned_data)

            return redirect("success")

    else:
        form = StudentForm()

    return render(
        request,
        "student_form.html",
        {"form": form},
    )


def success(request):
    return render(request, "success.html")
```

---

## 7. Understand the View

### GET request

When the user first opens:

```text
/student/
```

the request is normally `GET`.

This code runs:

```python
else:
    form = StudentForm()
```

Then Django displays the empty form:

```python
return render(
    request,
    "student_form.html",
    {"form": form},
)
```

---

## 8. POST Request

When the user clicks **Submit**, the browser sends a `POST` request.

Django receives the submitted data here:

```python
form = StudentForm(request.POST)
```

The submitted values are now connected to the form.

---

## 9. Validate the Form

This is the important part:

```python
if form.is_valid():
```

Django validates the submitted data according to the fields defined in `StudentForm`.

If the form is invalid, execution continues to:

```python
return render(
    request,
    "student_form.html",
    {"form": form},
)
```

Django will display the form again, including validation errors.

If the form is valid, Django enters the success block.

---

# 10. Access Cleaned Data

After:

```python
if form.is_valid():
```

you can access validated data using:

```python
form.cleaned_data
```

For example:

```python
print(form.cleaned_data)
```

It may look like:

```python
{
    "name": "John",
    "dob": datetime.date(2000, 5, 10),
    "gender": "Male",
}
```

### Important

Use `cleaned_data` **after** `form.is_valid()`.

Do not rely on `cleaned_data` before validation.

---

# 11. Redirect to the Success Page

After successful validation:

```python
return redirect("success")
```

The name comes from:

```python
path("success/", views.success, name="success")
```

So:

```python
redirect("success")
```

means:

> Find the URL whose Django name is `success` and redirect the browser there.

This is better than hard-coding the URL in the view:

```python
# Avoid when a named URL is available
return redirect("/student/success/")
```

Prefer:

```python
return redirect("success")
```

because Django's URL name remains the source of truth.

---

# 12. Why Redirect After POST?

The redirect prevents the browser from remaining on the form's POST response.

The flow becomes:

```text
GET
 |
 v
Student Form
 |
 | Submit
 v
POST
 |
 v
Validate Form
 |
 +---- invalid ----> Show Form + Errors
 |
 +---- valid -----> Process Data
                       |
                       v
                    Redirect
                       |
                       v
                  Success Page
```

This is commonly called **Post/Redirect/Get (PRG)**.

It also helps prevent accidental form resubmission when the user refreshes the success page.

```html
        <button type="submit">Submit</button>
    </form>

</body>
</html>
```

---

# 15. Why `{% csrf_token %}`?

For a POST form, include:

```django
{% csrf_token %}
```

Django uses a CSRF token to help protect POST requests against **Cross-Site Request Forgery** attacks.

For normal Django POST forms, this should be included inside the `<form>` element.

---

# 16. `{{ form }}` vs `{{ form.as_p }}`

You can render the form simply with:

```django
{{ form }}
```

A cleaner beginner-friendly option is:

```django
{{ form.as_p }}
```

This renders each form field inside a paragraph element.

You can also render fields manually when you need more control:

```html
<p>
    {{ form.name.label_tag }}
    {{ form.name }}
    {{ form.name.errors }}
</p>
```

For learning the basics, `{{ form.as_p }}` is convenient.

# 21. Key Concepts to Remember

### Form creation

```python
class StudentForm(forms.Form):
```

Defines the fields and validation rules.

### GET

```python
if request.method == "POST":
    ...
else:
    form = StudentForm()
```

GET normally displays a fresh/empty form.

### POST

```python
form = StudentForm(request.POST)
```

Binds submitted request data to the form.

### Validation

```python
form.is_valid()
```

Checks whether the submitted data satisfies the form's validation rules.

### Validated data

```python
form.cleaned_data
```

Contains cleaned/validated values after successful validation.

### Redirect

```python
return redirect("success")
```

Sends the browser to the success URL after successful processing.

### Render

```python
return render(request, "student_form.html", {"form": form})
```

Renders an HTML template and passes the form to it.

# 22. One Important Improvement

The current example only prints the submitted data:

```python
print(form.cleaned_data)
```

This does **not save the student to a database**.

If the goal later becomes:

> Submit the form → save student → redirect to success page

then the next step is to create a Django `Model`, run migrations, and either use a `ModelForm` or save the validated data manually.

The current project is therefore a good example of:

```text
HTML Form
   ↓
Django Form
   ↓
POST Request
   ↓
Validation
   ↓
cleaned_data
   ↓
Redirect
   ↓
Success Page
```
