# 1. Introduction to Django Forms

## What is a Form?

A **form** is a way for users to enter and submit information to a website.

For example, a website might ask a user to enter:

-  Name 
-  Email 
-  Age 
-  Phone number 
-  Feedback 
-  Course selection 

A form provides the interface through which the user enters this data.


## How does a form work?

Suppose a student enters:

```
Name: Ravi
Age: 20
Email: ravi@example.com
```

The browser sends this information to the Django server.

Django can then:

1.  Receive the submitted data. 
2.  Check whether the data is valid. 
3.  Clean the data. 
4.  Give us the validated data. 
5.  Allow the application to decide what to do with it. 

---

## Why does Django provide a Forms framework?

We could create forms using plain HTML.

However, Django Forms provide useful functionality such as:

-  Validation 
-  Error handling 
-  Data cleaning 
-  Automatic field generation in HTML 
-  Re-displaying submitted values 
-  Consistent form processing 
-  Integration with Django's request/response system 

Instead of manually handling everything, Django gives us a structured way to define and process forms.

# 2. HTML Forms vs Django Forms

## HTML Form

A basic HTML form might look like this:

```
<form method="post">
    <input type="text" name="name">
    <input type="number" name="age">
    <input type="email" name="email">

    <button type="submit">Submit</button>
</form>
```

HTML is responsible mainly for creating the form interface in the browser.

---

## Django Form

With Django Forms, we define the fields in Python:

```
from django import forms


class StudentForm(forms.Form):
    name = forms.CharField()
    age = forms.IntegerField()
    email = forms.EmailField()
```

Django can then use this Python class to:

-  Generate form fields 
-  Validate submitted values 
-  Display errors 
-  Clean submitted data 
-  Render the form in a template

# 5. Form Field Options

Django fields accept many useful options.

| Option | Purpose | Example |
|---|---|---|
| `required` | Makes the field required or optional | `required=True` |
| `label` | Sets the label displayed to the user | `label="Student Name"` |
| `initial` | Provides an initial/default value | `initial="John"` |
| `help_text` | Displays additional information or instructions | `help_text="Enter your full name."` |
| `disabled` | Prevents the user from editing the field | `disabled=True` |
| `validators` | Adds custom validation functions | `validators=[validate_name]` |
| `error_messages` | Customizes Django's default error messages | `error_messages={"required": "Please enter your name."}` |
| `widget` | Controls how the field is represented in HTML | `widget=forms.TextInput()` |

---

## Quick Example
```
name = forms.CharField(
    required=True,
    label="Student Name",
    initial="John",
    help_text="Enter your full name.",
    disabled=False,
    validators=[],
    error_messages={
        "required": "Please enter your name."
    },
    widget=forms.TextInput()
)
```

# 6. Widgets

## What is a Widget?

A **widget** controls how a Django Form field is displayed as HTML.

Think of it like this:

```
Field
  ↓
What type of data is expected?
  ↓
Widget
  ↓
How should the field appear in HTML?
```

For example:

```
name = forms.CharField()
```

The field expects text.

A widget determines how that text field is displayed.

---

## Field vs Widget

| FieldWidget                 |                               |
| --------------------------- | ----------------------------- |
| Handles data and validation | Controls HTML representation  |
| Defines expected data       | Defines how the input appears |
| Example: `CharField`        | Example: `TextInput`          |
| Example: `EmailField`       | Example: `EmailInput`         |

Example:

```
email = forms.EmailField(
    widget=forms.EmailInput()
)
```

Here:

```
EmailField → data/validation
EmailInput → HTML representation
```

---

We can customize the generated HTML using `widget`.

For example:

```
name = forms.CharField(
    widget=forms.TextInput(
        attrs={
            "class": "form-control",
            "placeholder": "Enter your name"
        }
    )
)
```

# 8. GET and POST

A form page normally needs to handle two situations.

## GET

The user visits the page.

Example:

```
GET /student/
```

We display an empty form.

---

## POST

The user submits the form.

Example:

```
POST /student/
```

We receive the submitted data.

---

## Complete view

Update `students/views.py`:

```
from django.shortcuts import render
from .forms import StudentForm


def student_form(request):

    if request.method == "POST":
        form = StudentForm(request.POST)

        if form.is_valid():
            print(form.cleaned_data)

    else:
        form = StudentForm()

    return render(
        request,
        "students/student_form.html",
        {"form": form}
    )
```

---

## Understand the flow

### User visits the page

```
GET
 ↓
StudentForm()
 ↓
Display empty form
```

### User submits the form

```
POST
 ↓
request.POST
 ↓
StudentForm(request.POST)
 ↓
form.is_valid()
 ↓
cleaned_data
```

---

## Why check `request.method`?

Because we need different behavior.

```
if request.method == "POST":
```

means:

> The user submitted the form.

Otherwise:

```
else:
    form = StudentForm()
```

means:

> The user is simply opening the form page.

## Comparison

| UnboundBound               |                                |
| -------------------------- | ------------------------------ |
| `StudentForm()`            | `StudentForm(request.POST)`    |
| No submitted data          | Submitted data attached        |

>

# 10 Django Form Validation

Validation means checking whether the data entered by the user is correct.

Django form validation can be divided into 3 types:

| Type                          | What it means                                 | Example                            |
| ----------------------------- | --------------------------------------------- | ---------------------------------- |
| Built-in Validation           | Django automatically checks basic rules       | `EmailField()` checks email format |
| Field-Level Custom Validation | We create a custom rule for one field         | Email must end with `@example.com` |
| Form-Level Custom Validation  | We create a custom rule using multiple fields | Passwords must match               |

---

## 1. Built-in Validation

Django form fields already have basic validation rules.

```python
class StudentForm(forms.Form):
    name = forms.CharField()
    age = forms.IntegerField()
    email = forms.EmailField()
```

Django automatically checks the data based on the field type.

| Field          | Input            | Result  |
| -------------- | ---------------- | ------- |
| `CharField`    | `Ravi`           | Valid   |
| `IntegerField` | `20`             | Valid   |
| `IntegerField` | `twenty`         | Invalid |
| `EmailField`   | `ravi@gmail.com` | Valid   |
| `EmailField`   | `hello`          | Invalid |

---

## 2. Field-Level Custom Validation

Sometimes Django's built-in validation is not enough.

For example:

```python
email = forms.EmailField()
```

allows:

```text
ravi@gmail.com
ravi@yahoo.com
ravi@example.com
```

All three can be valid email formats.

But suppose our application has a rule:

```text
Only @example.com emails are allowed.
```

This is our own rule, so we need custom validation.

For one field, we use:

```python
clean_<fieldname>()
```

For the `email` field:

```python
def clean_email(self):
```

Example:

```python
class StudentForm(forms.Form):

    email = forms.EmailField()

    def clean_email(self):

        email = self.cleaned_data["email"]

        if not email.endswith("@example.com"):
            raise forms.ValidationError(
                "Please use an example.com email address."
            )

        return email
```

Here:

```python
email = forms.EmailField()
```

does the built-in validation.

Then:

```python
clean_email()
```

does our custom validation.

| Email              | Built-in Validation | Custom Validation | Result  |
| ------------------ | ------------------- | ----------------- | ------- |
| `ravi@example.com` | Valid               | Valid             | Valid   |
| `ravi@gmail.com`   | Valid               | Invalid           | Invalid |
| `hello`            | Invalid             | Not reached       | Invalid |

**Simple meaning:**

> Field-level custom validation = Our own rule for one field.

---

## 3. Form-Level Custom Validation

Sometimes the validation rule depends on multiple fields.

For example:

```text
password
confirm_password
```

We want to check:

```text
Are both passwords the same?
```

For this type of validation, we use:

```python
clean()
```

Example:

```python
class StudentForm(forms.Form):

    password = forms.CharField()

    confirm_password = forms.CharField()

    def clean(self):

        cleaned_data = super().clean()

        password = cleaned_data.get("password")

        confirm_password = cleaned_data.get("confirm_password")

        if password != confirm_password:
            raise forms.ValidationError(
                "Passwords do not match."
            )

        return cleaned_data
```

Here we are checking two fields together:

```text
password
    +
confirm_password
    ↓
Do they match?
```

**Simple meaning:**

> Form-level custom validation = Our own rule involving multiple fields.

---

## `clean_<field>()` vs `clean()`

| MethodUse         |                                                |
| ----------------- | ---------------------------------------------- |
| `clean_<field>()` | Validate one specific field                    |
| `clean()`         | Validate relationships between multiple fields |

Think:

```
One field
   ↓
clean_email()
```

and:

```
Multiple fields
   ↓
clean()
```

# 11. Custom Error Messages

Django provides default error messages.

We can customize them.

```
name = forms.CharField(
    error_messages={
        "required": "Please enter your name."
    }
)
```

Now, if the field is empty, Django uses our custom message.

---

## Example

```
class StudentForm(forms.Form):
    name = forms.CharField(
        error_messages={
            "required": "Student name is required."
        }
    )

    age = forms.IntegerField(
        error_messages={
            "required": "Please enter your age."
        }
    )

    email = forms.EmailField(
        error_messages={
            "required": "Please enter your email."
        }
    )
```

Custom messages are useful because they can be:

-  More understandable 
-  More specific 
-  Consistent with the application's language
