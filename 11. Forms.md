# 1. Introduction to Django Forms

## What is a Form?

A **form** is a way for users to enter and submit information to a website.

For example, a website might ask a user to enter:

-  Name 
-  Email 
-  Age 
-  Phone number 
-  Feedback 
-  Course selection 

A form provides the interface through which the user enters this data.


## How does a form work?

Suppose a student enters:

```
Name: Ravi
Age: 20
Email: ravi@example.com
```

The browser sends this information to the Django server.

Django can then:

1.  Receive the submitted data. 
2.  Check whether the data is valid. 
3.  Clean the data. 
4.  Give us the validated data. 
5.  Allow the application to decide what to do with it. 

---

## Why does Django provide a Forms framework?

We could create forms using plain HTML.

However, Django Forms provide useful functionality such as:

-  Validation 
-  Error handling 
-  Data cleaning 
-  Automatic field generation in HTML 
-  Re-displaying submitted values 
-  Consistent form processing 
-  Integration with Django's request/response system 

Instead of manually handling everything, Django gives us a structured way to define and process forms.

---

# 2. HTML Forms vs Django Forms

## HTML Form

A basic HTML form might look like this:

```
<form method="post">
    <input type="text" name="name">
    <input type="number" name="age">
    <input type="email" name="email">

    <button type="submit">Submit</button>
</form>
```

HTML is responsible mainly for creating the form interface in the browser.

---

## Django Form

With Django Forms, we define the fields in Python:

```
from django import forms


class StudentForm(forms.Form):
    name = forms.CharField()
    age = forms.IntegerField()
    email = forms.EmailField()
```

Django can then use this Python class to:

-  Generate form fields 
-  Validate submitted values 
-  Display errors 
-  Clean submitted data 
-  Render the form in a template

# 9. Widgets

## What is a Widget?

A **widget** controls how a Django Form field is displayed as HTML.

Think of it like this:

```
Field
  ↓
What type of data is expected?
  ↓
Widget
  ↓
How should the field appear in HTML?
```

For example:

```
name = forms.CharField()
```

The field expects text.

A widget determines how that text field is displayed.

---

## Field vs Widget

| FieldWidget                 |                               |
| --------------------------- | ----------------------------- |
| Handles data and validation | Controls HTML representation  |
| Defines expected data       | Defines how the input appears |
| Example: `CharField`        | Example: `TextInput`          |
| Example: `EmailField`       | Example: `EmailInput`         |

Example:

```
email = forms.EmailField(
    widget=forms.EmailInput()
)
```

Here:

```
EmailField → data/validation
EmailInput → HTML representation
```

---

# 16. GET and POST

A form page normally needs to handle two situations.

## GET

The user visits the page.

Example:

```
GET /student/
```

We display an empty form.

---

## POST

The user submits the form.

Example:

```
POST /student/
```

We receive the submitted data.

---

## Complete view

Update `students/views.py`:

```
from django.shortcuts import render
from .forms import StudentForm


def student_form(request):

    if request.method == "POST":
        form = StudentForm(request.POST)

        if form.is_valid():
            print(form.cleaned_data)

    else:
        form = StudentForm()

    return render(
        request,
        "students/student_form.html",
        {"form": form}
    )
```

---

## Understand the flow

### User visits the page

```
GET
 ↓
StudentForm()
 ↓
Display empty form
```

### User submits the form

```
POST
 ↓
request.POST
 ↓
StudentForm(request.POST)
 ↓
form.is_valid()
 ↓
cleaned_data
```

---

## Why check `request.method`?

Because we need different behavior.

```
if request.method == "POST":
```

means:

> The user submitted the form.

Otherwise:

```
else:
    form = StudentForm()
```

means:

> The user is simply opening the form page.

# 17. Bound and Unbound Forms

This is a very important concept.

## Unbound Form

```
form = StudentForm()
```

An unbound form has no submitted data attached to it.

Usually used when displaying a fresh form.

```
StudentForm()
    ↓
Unbound
    ↓
Empty/new form
```

---

## Bound Form

```
form = StudentForm(request.POST)
```

A bound form has submitted data attached to it.

```
request.POST
    ↓
StudentForm(request.POST)
    ↓
Bound form
```

---

## Comparison

| UnboundBound               |                                |
| -------------------------- | ------------------------------ |
| `StudentForm()`            | `StudentForm(request.POST)`    |
| No submitted data          | Submitted data attached        |
| Used to display a new form | Used to process submitted data |
| `is_bound` is false        | `is_bound` is true             |

> **Easy way to remember:**
>
> **Unbound = no user-submitted data.**
>
> **Bound = submitted data is attached.**

# 18. Form Validation

## What is validation?

Validation means checking whether submitted data meets the rules required by the form.

For example:

```
age = forms.IntegerField()
```

expects an integer.

If the user submits:

```
twenty
```

the value is invalid.

Similarly:

```
email = forms.EmailField()
```

expects a valid email format.

---

## `is_valid()`

We validate a form using:

```
form.is_valid()
```

Example:

```
if form.is_valid():
    print(form.cleaned_data)
```

If validation succeeds:

```
form.is_valid()
```

returns:

```
True
```

Otherwise:

```
False
```

---

## `cleaned_data`

After successful validation:

```
form.cleaned_data
```

contains the cleaned values.

For example:

```
{
    "name": "Ravi",
    "age": 20,
    "email": "ravi@example.com"
}
```

> **Important:** Access `cleaned_data` after validation. Do not assume it contains successfully validated values before calling `is_valid()`.

---

## What happens during validation?

At a beginner-friendly level:

```
Submitted data
      ↓
Form receives data
      ↓
is_valid()
      ↓
Field validation
      ↓
Custom validation
      ↓
Cleaned data
      ↓
cleaned_data
```

If something is wrong:

```
Validation
    ↓
Error
    ↓
form.errors
```

# 20. Custom Validation

Sometimes built-in validation isn't enough.

For example, perhaps our application requires:

```
@example.com
```

email addresses.

We can create custom validation.

---

## Field-Level Validation

In `forms.py`:

```
from django import forms


class StudentForm(forms.Form):
    name = forms.CharField()
    age = forms.IntegerField()
    email = forms.EmailField()

    def clean_email(self):
        email = self.cleaned_data["email"]

        if not email.endswith("@example.com"):
            raise forms.ValidationError(
                "Please use an example.com email address."
            )

        return email
```

---

## What is `clean_email()`?

The pattern is:

```
clean_<fieldname>()
```

For the field:

```
email
```

we create:

```
clean_email()
```

Django uses this method during validation.

---

## Step by step

### Get the cleaned email

```
email = self.cleaned_data["email"]
```

### Check it

```
if not email.endswith("@example.com"):
```

### Raise an error

```
raise forms.ValidationError(
    "Please use an example.com email address."
)
```

### Return the valid value

```
return email
```

---

## Why return the value?

The cleaned value needs to continue through the form's validation process.

So:

```
return email
```

is important when validation succeeds.

---

# 21. Form-Level Validation

Sometimes validation depends on **multiple fields**.

For example:

```
Age
Course
```

Suppose students under 18 cannot select an advanced course.

This rule depends on more than one field.

We can use:

```
def clean(self):
    cleaned_data = super().clean()

    ...

    return cleaned_data
```

Example:

```
class StudentForm(forms.Form):
    name = forms.CharField()
    age = forms.IntegerField()
    course = forms.ChoiceField(
        choices=[
            ("basic", "Basic"),
            ("advanced", "Advanced"),
        ]
    )

    def clean(self):
        cleaned_data = super().clean()

        age = cleaned_data.get("age")
        course = cleaned_data.get("course")

        if age is not None and course == "advanced" and age < 18:
            raise forms.ValidationError(
                "Students under 18 cannot select the advanced course."
            )

        return cleaned_data
```

---

## Why use `get()`?

During validation, another field may already contain an error.

Using:

```
cleaned_data.get("age")
```

is safer than assuming the value always exists.

---

## `clean_<field>()` vs `clean()`

| MethodUse         |                                                |
| ----------------- | ---------------------------------------------- |
| `clean_<field>()` | Validate one specific field                    |
| `clean()`         | Validate relationships between multiple fields |

Think:

```
One field
   ↓
clean_email()
```

and:

```
Multiple fields
   ↓
clean()
```

# 31. CSRF Protection

## What is CSRF?

CSRF stands for:

```
Cross-Site Request Forgery
```

It is a type of attack where an attacker attempts to make a user's browser submit an unwanted request to a website where the user is authenticated.

Django provides CSRF protection for unsafe requests such as POST requests.

---

## Django template

For POST forms, include:

```
{% csrf_token %}
```

Example:

```
<form method="post">
    {% csrf_token %}

    {{ form }}

    <button type="submit">Submit</button>
</form>
```

---

## Why is it needed?

The CSRF token helps Django verify that the POST request is associated with the legitimate form/session rather than an unauthorized cross-site request.

> **Beginner rule:** When creating a Django POST form, remember `{% csrf_token %}`.

# Step 4 — Create `forms.py`

```
from django import forms


class StudentForm(forms.Form):

    COURSE_CHOICES = [
        ("python", "Python"),
        ("django", "Django"),
        ("java", "Java"),
    ]

    name = forms.CharField(
        label="Student Name",
        help_text="Enter your full name.",
        widget=forms.TextInput(
            attrs={
                "class": "form-control",
                "placeholder": "Enter your name",
            }
        ),
        error_messages={
            "required": "Please enter your name."
        }
    )

    age = forms.IntegerField(
        label="Age",
        widget=forms.NumberInput(
            attrs={
                "class": "form-control",
                "placeholder": "Enter your age",
            }
        )
    )

    email = forms.EmailField(
        label="Email",
        widget=forms.EmailInput(
            attrs={
                "class": "form-control",
                "placeholder": "Enter your email",
            }
        )
    )

    course = forms.ChoiceField(
        label="Course",
        choices=COURSE_CHOICES,
        widget=forms.Select(
            attrs={
                "class": "form-control"
            }
        )
    )

    def clean_email(self):
        email = self.cleaned_data["email"]

        if not email.endswith("@example.com"):
            raise forms.ValidationError(
                "Please use an example.com email address."
            )

        return email

    def clean(self):
        cleaned_data = super().clean()

        age = cleaned_data.get("age")
        course = cleaned_data.get("course")

        if age is not None and course == "django" and age < 18:
            raise forms.ValidationError(
                "Students under 18 cannot register for Django."
            )

        return cleaned_data
```

```
from django.shortcuts import render
from .forms import StudentForm


def student_form(request):

    success_message = None

    if request.method == "POST":
        form = StudentForm(request.POST)

        if form.is_valid():
            data = form.cleaned_data

            print(data)

            success_message = (
                "Student registration submitted successfully."
            )

            form = StudentForm()

    else:
        form = StudentForm()

    return render(
        request,
        "students/student_form.html",
        {
            "form": form,
            "success_message": success_message,
        }
    )
```

### Problem

```

    {{ form }}
</form>
```

### Cause

CSRF token is missing.

### Solution

```
<form method="post">
    {% csrf_token %}

    {{ form }}
</form>
```

## Mistake 2 — Forgetting `method="post"`

### Problem

```
<form>
```

### Cause

### Solution

```
<form method="post">
```

## Mistake 3 — Not checking `request.method`

### Problem

```
if request.method == "POST":
    ...
```

## Answers

### 1. What is a Django Form?

A Django Form is a Python class used to define form fields, validate submitted data, clean data, and handle form errors.

---

### 2. What is `forms.Form`?

`forms.Form` is Django's base class for creating forms that are not directly tied to a database model.

Example:

```
class StudentForm(forms.Form):
    name = forms.CharField()
```

---

### 3. Why use Django Forms?

They provide:

-  Field definitions 
-  Validation 
-  Error handling 
-  Data cleaning 
-  Convenient rendering 

---

### 4. What is a form field?

A field defines the type of data expected from the user.

Example:

```
age = forms.IntegerField()
```

---

### 5. What is a bound form?

A form with submitted data attached:

```
StudentForm(request.POST)
```

---

### 6. What is an unbound form?

A form without submitted data:

```
StudentForm()
```

---

### 7. What is `is_valid()`?

It runs form validation and returns:

```
True
```

if the submitted data is valid, otherwise:

```
False
```

---

### 8. What is `cleaned_data`?

A dictionary containing successfully cleaned and validated form data.

```
form.cleaned_data
```

---

### 9. What is a widget?

A widget controls how a form field is represented as HTML.

Example:

```
forms.TextInput()
```

---

### 10. What is CSRF?

CSRF stands for Cross-Site Request Forgery. Django's CSRF protection helps prevent unauthorized cross-site requests.

---

### 11. Field vs widget?

A field handles data and validation.

A widget controls the HTML representation.

```
Field  → data/validation
Widget → HTML
```

---

### 12. GET vs POST?

GET is commonly used to request/retrieve information.

POST is commonly used to submit data that changes or sends information to the server.

---

### 13. What is `request.POST`?

It contains data submitted through a POST request.

---

### 14. What is `request.FILES`?

It contains uploaded files submitted through a form.

---

### 15. What is `clean_<field>()`?

A method used for custom validation of a specific field.

Example:

```
def clean_email(self):
    ...
```

---

### 16. What is `clean()`?

A form-level validation method, especially useful when multiple fields depend on each other.

---

### 17. What is `ValidationError`?

An exception used to indicate that submitted data is invalid.

```
raise forms.ValidationError("Invalid value.")
```

---

### 18. How do you make a field optional?

Use:

```
required=False
```

Example:

```
phone = forms.CharField(required=False)
```

---

### 19. How do you customize an error message?

Use:

```
error_messages={
    "required": "Please enter your name."
}
```

---

### 20. How do you customize a widget?

Use the `widget` argument:

```
name = forms.CharField(
    widget=forms.TextInput(
        attrs={
            "class": "form-control"
        }
    )
)
```
