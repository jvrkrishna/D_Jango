# PART A — UNDERSTANDING PYTHON ENVIRONMENTS

## 1. What Is a Python Environment?

Before learning Django, must understand:

> **Where are Python and Python packages installed?**

If Python is installed on a computer, it is available through the system/global Python installation.

```text
Windows Computer
│
└── Python
    │
    ├── pip
    ├── Django
    ├── requests
    └── other packages
```

---

# 2. The Problem With Global Packages

Imagine we have two projects:

```text
Project A
Needs Django version A

Project B
Needs Django version B
```

If both projects use the same global Python environment, package changes can affect other projects.

This can create:

> **Dependency conflicts**

For example:

```text
Project A
Django 5.x

Project B
Django 4.x
```

If both depend on the same global installation, upgrading Django for Project A may affect Project B.

---

# 3. Solution — Virtual Environments

Instead, each project can have its own isolated environment.

```text
Computer
│
├── Global Python
│
├── CampusQuest
│   └── venv
│
└── AnotherProject
    └── venv
```

For CampusQuest:

```text
CampusQuest
│
└── venv
    ├── Django
    ├── Django REST Framework
    ├── mysqlclient
    └── python-dotenv
```

> **A virtual environment isolates a project's Python dependencies from other projects and the system Python installation.**

---

# 4. Simple Student Analogy

Imagine every student has a separate toolbox:

```text
Student A
└── Toolbox

Student B
└── Toolbox

Student C
└── Toolbox
```

Changing Student A's tools does not affect Student B.

A Python virtual environment works similarly.

> **One project = one isolated Python environment**

# 5. What Is `venv`?

Python provides a built-in module called:

```text
venv
```

It creates virtual environments.

Command:

```cmd
python -m venv venv
```

Explanation:

```text
python
```

Use Python.

```text
-m
```

Run a Python module.

```text
venv
```

Python's built-in virtual-environment module.

The final:

```text
venv
```

is the name of the environment folder.

On Windows, you will normally see:

```text

│
├── Include
├── Lib
```

The important folder for Windows is:


It contains the executables and activation scripts for the environment.

# 10. How Do We Know the Environment Exists?

There is no standard command such as:

```cmd
python list environments
```

for Python's built-in `venv`.

Instead, inspect the project folder:

```cmd
dir
```

You should see:

```text
venv
```

You can also inspect:

```cmd
dir venv
```

and:

```cmd
dir venv\Scripts
```

---

# 11. Important: Python `venv` Does Not Have a Global Environment List

With standard Python `venv`, there is no central registry containing every environment on your computer.

For example:

```text
C:\Projects\CampusQuest\venv
C:\Projects\CollegeApp\venv
D:\PythonProjects\ShopApp\venv
```

Python does not automatically provide:

```cmd
python --list-environments
```

You normally locate environments by their directories.

This is different from Conda.

Creating an environment does **not** automatically activate it.

From the project directory:

```cmd

```

After activation:

```text

```

The important part is:

```text
(venv)
```

# 13. What Does Activation Mean?

Activation configures the current Command Prompt session so that Python and package commands use the virtual environment.

Before activation:

```text
python
   ↓
Global/System Python
```

After activation:

```text
python
   ↓
CampusQuest\venv Python
```

# 22. What Does Deactivate Mean?

Deactivation does **not** delete the environment.

It only stops using the environment in the current Command Prompt session.

```text
Activate
   ↓
Start using environment

Deactivate
   ↓
Stop using environment
```

The environment remains on disk.

# 24. Delete a Virtual Environment

First deactivate it:

```cmd
deactivate
```

Then delete the folder:

```cmd
rmdir /s /q venv
```

⚠️ `rmdir /s /q` permanently deletes the directory and its contents without asking for confirmation.

For beginners, deleting the `venv` folder through File Explorer is also possible.

---

# 25. Recreate a Virtual Environment

After deleting:

```cmd
python -m venv venv
```

Then:

```cmd
venv\Scripts\activate
```

This creates a fresh environment.

Packages such as Django must be installed again.

# PART A.1 — `venv` vs ANACONDA / CONDA

# 28. What Is Anaconda?

Anaconda is a Python distribution commonly used for:

- Data science
- Scientific computing
- Machine learning
- Analytics
- Jupyter-based workflows

It includes tools for managing environments and packages.

---

# 29. What Is Conda?

Conda is an environment and package management system.

It can create isolated environments.

Example:

```cmd
conda create -n campusquest python
```

Activate:

```cmd
conda activate campusquest
```

Deactivate:

```cmd
conda deactivate
```

List Conda environments:

```cmd
conda env list
```

---

# 30. `venv` vs Conda

| Feature | Python `venv` | Conda |
|---|---|---|
| Included with standard Python | Yes | No |
| Creates isolated environments | Yes | Yes |
| Package manager | Usually pip | conda and/or pip |
| Manages non-Python dependencies | Limited | Strong |
| Django projects | Excellent | Possible |
| Data science ecosystem | Basic | Excellent |
| Requires separate installation | No | Yes |
| Simple for Django beginners | Yes | More tooling |
| Central environment listing | No | Yes |

---

For CampusQuest:

# PART A.2 — PIP, FREEZE & requirements.txt

# 33. What Is `requirements.txt`?

`requirements.txt` is a text file that tells Python:

> **These are the packages and versions required to run this project.**

Conceptually:

```text
Django==5.x.x
djangorestframework==3.x.x
mysqlclient==2.x.x
python-dotenv==1.x.x
```

The exact versions depend on what is installed.

---

# 34. What Does "Freeze" Mean?

When we run:

```cmd
python -m pip freeze
```

pip displays the packages currently installed in the active virtual environment, along with their versions.

Example:

```text
Django==5.2.x
djangorestframework==3.16.x
mysqlclient==2.2.x
python-dotenv==1.1.x
```

Therefore:

> **Freezing means taking a snapshot of the installed Python dependencies and their versions.**

It does NOT mean:

- Freezing Python
- Freezing the project
- Making packages unchangeable

It simply creates a dependency snapshot.

---

# 35. `pip list` vs `pip freeze`

### `pip list`

Shows installed packages in a readable list:

```cmd
python -m pip list
```

### `pip freeze`

Shows installed packages in a requirements-friendly format:

```cmd
python -m pip freeze
```

Example:

```text
Django==5.2.x
djangorestframework==3.16.x
mysqlclient==2.2.x
python-dotenv==1.1.x
```

---

# 36. Create `requirements.txt`

Run:

```cmd
python -m pip freeze > requirements.txt
```

Break the command down:

```text
python
   ↓
Run Python

-m pip
   ↓
Run pip through Python

freeze
   ↓
Show installed packages + versions

>
   ↓
Redirect output into a file

requirements.txt
   ↓
Save the output here
```

Therefore:

```cmd
python -m pip freeze > requirements.txt
```

means:

> "Take the installed packages and their versions and save them into `requirements.txt`."

---

# 37. View `requirements.txt`

Run:

```cmd
type requirements.txt
```

Or:

```cmd
notepad requirements.txt
```

You may see:

```text
asgiref==...
Django==...
djangorestframework==...
mysqlclient==...
python-dotenv==...
sqlparse==...
tzdata==...
```

---

# 38. Why Are There More Packages Than We Installed?

You may install:

```text
Django
Django REST Framework
mysqlclient
python-dotenv
```

but `requirements.txt` may contain additional packages.

This is normal.

Some packages have dependencies.

For example:

```text
Django
  ├── asgiref
  ├── sqlparse
  └── other dependencies
```

Therefore `pip freeze` records the complete installed environment.

---

# 39. If We Want Only the Main Four Packages

We can manually create:

```cmd
notepad requirements.txt
```

and write:

```text
Django
djangorestframework
mysqlclient
python-dotenv
```

However, these are not pinned to exact versions.

For a reproducible project, version-pinned dependencies are generally preferable.

For this course, students should learn the standard approach:

```cmd
python -m pip freeze > requirements.txt
```

---

# 40. Why Do We Need Versions?

Suppose today we install:

```text
Django 5.2.x
```

Later another developer installs a newer Django version.

There may be compatibility differences.

A frozen requirements file can contain:

```text
Django==5.2.x
```

The `==` means:

> Install this exact version.

This helps keep development environments consistent.

---

# 41. Install Everything From requirements.txt

Suppose another student receives the CampusQuest source code.

They create an environment:

```cmd
python -m venv venv
```

Activate:

```cmd
venv\Scripts\activate
```

Then instead of installing every package separately:

```cmd
python -m pip install -r requirements.txt
```

This installs everything listed in the file.

Flow:

```text
requirements.txt
       ↓
Create venv
       ↓
Activate
       ↓
pip install -r requirements.txt
       ↓
Dependencies installed
       ↓
Project ready
```

---

# 42. The Complete Dependency Workflow

```text
Create venv
     ↓
Activate venv
     ↓
pip install packages
     ↓
pip freeze
     ↓
requirements.txt
     ↓
GitHub
     ↓
Another developer
     ↓
Create venv
     ↓
pip install -r requirements.txt
     ↓
Same dependency setup
```

This is an important professional development workflow.
