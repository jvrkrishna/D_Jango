# Day 2 — Python Virtual Environments & Django Installation

## 1. Virtual Environment

A **virtual environment** is an isolated Python environment for a project and its dependencies.

### Why do we need it?

Different projects may require different versions of Django or other packages.

```text
Project A → Django 5.x
Project B → Django 4.x
```

If both projects use the same global Python environment, installing or upgrading packages for one project can affect the other project and create **dependency conflicts**.

A separate virtual environment avoids this:

```text
Project A
└── venv

Project B
└── venv
```

---

## 2. What Is `venv`?

Python provides a built-in module called `venv` for creating virtual environments.

```cmd
python -m venv venv
```

Meaning:

```text
python → Run Python
-m     → Run a Python module
venv   → Python's virtual-environment module
venv   → Name of the environment folder
```

The last `venv` is simply the folder name. It can also be named something else:

```cmd
python -m venv myenv
python -m venv django_env
```

For this course, use:

```text
venv
```

---

## 3. Create the Project Folder

Open **Command Prompt** and run:

```cmd
cd Desktop
mkdir myproject
cd myproject
```

Check the current location:

```cmd
cd
```

The project path will look similar to:

```text
C:\Users\<username>\Desktop\myproject>
```

---

## 4. Create the Virtual Environment

Inside the project folder:

```cmd
python -m venv venv
```

This creates:

```text
myproject
└── venv
```

To check the folder:

```cmd
dir
```

To view the contents of `venv`:

```cmd
dir venv
```

You will normally see:

```text
venv
├── Include
├── Lib
├── Scripts
└── pyvenv.cfg
```

On Windows, the important folder is:

```text
Scripts
```

It contains the environment's Python executable and activation scripts.

---

## 5. Create vs Activate a Virtual Environment

Creating and activating are two different operations.

### Create

```cmd
python -m venv venv
```

This **creates** the environment.

### Activate

```cmd
venv\Scripts\activate
```

This **activates** the environment for the current Command Prompt session.

After activation, the prompt should look similar to:

```text
(venv) C:\Users\<username>\Desktop\myproject>
```

The important part is:

```text
(venv)
```

---

## 6. What Does Activation Do?

Activation makes the current command-line session use the virtual environment's Python and package tools.

```text
Before activation
python
  ↓
Global Python

After activation
python
  ↓
venv Python
```

Therefore, when Django is installed after activation, Django is installed into that project's virtual environment.

---

## 7. Verify Python

After activating the environment:

```cmd
where python
```

The virtual environment's Python should appear first, for example:

```text
C:\Users\<username>\Desktop\myproject\venv\Scripts\python.exe
```

Check the Python version:

```cmd
python --version
```

The exact version depends on the Python installation.

---

## 8. `pip`

`pip` is Python's package installer.

It is used to install and manage Python packages.

For this course, generally use:

```cmd
python -m pip
```

instead of simply:

```cmd
pip
```

This makes it clear that `pip` is being run through the Python interpreter currently being used.

### All important pip commands

```cmd
python -m pip --version

python -m pip install --upgrade pip

python -m pip install django

python -m pip list

python -m pip freeze

python -m pip freeze > requirements.txt

python -m pip install -r requirements.txt
```

Check pip:

```cmd
python -m pip --version
```

The output should point to the active virtual environment.

---

## 9. Check Installed Packages

```cmd
python -m pip list
```

A newly created virtual environment contains only a small set of packages.

Packages installed globally on the computer are not automatically copied into the new virtual environment.

This is the isolation provided by the virtual environment.

---

## 10. Upgrade `pip`

Before installing Django:

```cmd
python -m pip install --upgrade pip
```

This updates `pip` inside the active virtual environment.

---

## 11. Install Django

After activating the virtual environment:

```cmd
python -m pip install django
```

Because `(venv)` is active, Django is installed into the virtual environment.

The relationship is:

```text
Project
└── venv
    └── Django
```

Django also requires other Python packages, so `pip` installs its dependencies automatically.

---

## 12. Verify Django Installation

Check the Django version:

```cmd
python -m django --version
```

You can also check Django details:

```cmd
python -m pip show django
```

`pip show django` displays information such as:

```text
Name
Version
Location
Requires
```

---

## 13. Django Dependencies

A **dependency** is a package that another package requires to work properly.

For example:

```text
Django
├── asgiref
├── sqlparse
└── other dependencies
```

When Django is installed, `pip` automatically installs the packages Django needs.

---

## 14. `pip list` vs `pip freeze`

### `pip list`

```cmd
python -m pip list
```

Used mainly to view installed packages in a readable table.

### `pip freeze`

```cmd
python -m pip freeze
```

Used mainly to output installed packages with exact versions.

Example:

```text
Django==5.x.x
asgiref==...
sqlparse==...
tzdata==...
```

`pip freeze` does not freeze Python. It simply outputs the installed packages and their versions in a requirements-friendly format.

---

## 15. `requirements.txt`

A project usually needs a record of its Python dependencies.

This record is commonly stored in:

```text
requirements.txt
```

Example:

```text
Django==5.x.x
some-package==1.x.x
another-package==2.x.x
```

This allows the same dependencies to be installed in another environment.

### Create `requirements.txt`

```cmd
python -m pip freeze > requirements.txt
```

The flow is:

```text
python
  ↓
pip freeze
  ↓
Installed packages + versions
  ↓
requirements.txt
```

### View `requirements.txt`

```cmd
type requirements.txt
```

---

## 16. Install Dependencies from `requirements.txt`

Another developer can create a new virtual environment:

```cmd
python -m venv venv
venv\Scripts\activate
```

Then install the project's dependencies:

```cmd
python -m pip install -r requirements.txt
```

The workflow is:

```text
requirements.txt
       ↓
Create virtual environment
       ↓
Activate environment
       ↓
pip install -r requirements.txt
       ↓
Dependencies installed
```

This is a common Python project workflow.

---

## 17. Deactivate the Virtual Environment

To leave the active virtual environment:

```cmd
deactivate
```

The prompt changes from:

```text
(venv) C:\Users\<username>\Desktop\myproject>
```

to:

```text
C:\Users\<username>\Desktop\myproject>
```

The `(venv)` disappears.

### Important

`deactivate` does **not** delete the virtual environment.

It only stops using that virtual environment in the current Command Prompt session.

The `venv` folder remains on the computer.

---

## 18. Activate an Existing Environment Again

If the environment already exists:

```cmd
venv\Scripts\activate
```

The prompt should again show:

```text
(venv)
```

You can then use:

```cmd
python
python -m pip
```

from that environment.

---

## 19. Delete a Virtual Environment

First deactivate it:

```cmd
deactivate
```

Then delete the folder:

```cmd
rmdir /s /q venv
```

This permanently removes the `venv` directory.

The project source files outside `venv` are not deleted.

---

## 20. Recreate the Virtual Environment

Create it again:

```cmd
python -m venv venv
```

Activate it:

```cmd
venv\Scripts\activate
```

Install the dependencies:

```cmd
python -m pip install -r requirements.txt
```

This recreates the Python environment from the dependency file.

---

## 21. `venv` vs Conda

Python provides `venv` as part of the standard Python installation.

Conda is another environment and package-management system.

For this Django course, use:

```text
Python
  ↓
venv
  ↓
pip
  ↓
Django
```

There is no need to use Conda for this setup.

---

## 22. Complete Django Setup

Run these commands in order:

```cmd
cd Desktop
mkdir myproject
cd myproject

python -m venv venv
venv\Scripts\activate

python --version
where python

python -m pip --version
python -m pip install --upgrade pip

python -m pip install django

python -m django --version
python -m pip list

python -m pip freeze > requirements.txt
type requirements.txt
```

At this stage, the project looks like:

```text
myproject
├── venv
│   ├── Include
│   ├── Lib
│   ├── Scripts
│   └── pyvenv.cfg
└── requirements.txt
```

The Python environment contains Django and its required dependencies.
