# PART 1 — UNDERSTAND PYTHON ENVIRONMENTS

## 1. Why Do We Need a Virtual Environment?

Before installing Django, understand one important problem.

A computer can have Python installed globally:

```text
Windows
   │
   └── Python
       ├── pip
       ├── Django
       ├── requests
       └── other packages
```

Now imagine you have two projects:

```text
Project A → Django 5.x
Project B → Django 4.x
```

If both projects use the same global Python packages, changing a package for Project A could affect Project B.

This is called a **dependency conflict**.

### Solution

Each project gets its own isolated Python environment:

```text
Computer
│
├── Global Python
│
├── CampusQuest
│   └── venv
│
└── AnotherProject
    └── venv
```

Therefore:

> **A virtual environment isolates a project's Python dependencies from other projects and from the system Python installation.**

# PART 2 — PYTHON `venv`

## 2. What Is `venv`?

Python provides a built-in module called `venv`.

It is used to create virtual environments.

The command is:

```cmd
python -m venv venv
```

Understand the command:

```text
python
   ↓
Use Python

-m
   ↓
Run a Python module

venv
   ↓
Python's virtual-environment module

venv
   ↓
Name of the environment folder
```

The last `venv` is simply the folder name.

You could also write:

```cmd
python -m venv myenv
```

or:

```cmd
python -m venv django_env
```

But for CampusQuest, we will use:

```text
venv
```

# PART 6 — ACTIVATE THE ENVIRONMENT

## 6. Creating vs Activating

This distinction is very important.

Creating:

```cmd
python -m venv venv
```

**creates** the environment.

It does **not** automatically activate it.

To activate it:

```cmd
venv\Scripts\activate
```

Your Command Prompt should change to something like:

```text
(venv) C:\Users\jvrkr\Desktop\CampusQuest>
```

The important part is:

```text
(venv)
```

---

# PART 7 — WHAT ACTIVATION DOES

## 7. What Does Activation Mean?

Activation tells the current Command Prompt session to use the virtual environment's Python and package commands.

Conceptually:

### Before activation

```text
python
   ↓
Global/System Python
```

### After activation

```text
python
   ↓
CampusQuest\venv Python
```

## 10. Check pip

`pip` is Python's package installer.

Run:

```cmd
python -m pip --version
```

The output should point to the active virtual environment.

For this course, prefer:

```cmd
python -m pip
```

instead of simply:

```cmd
pip
```

Why?

Because:

```text
python
   ↓
the Python interpreter we are using

-m pip
   ↓
pip belonging to that Python
```

This helps avoid accidentally installing packages into the wrong Python environment.

# PART 13 — `pip freeze`

## 19. What Does `pip freeze` Do?

Run:

```cmd
python -m pip freeze
```

It displays the packages installed in the active environment together with their versions.

For example:

```text
Django==5.x.x
djangorestframework==3.x.x
mysqlclient==2.x.x
python-dotenv==1.x.x
```

Think of it as:

> **A snapshot of the current Python dependencies and their versions.**

It does not freeze Python.

It does not make packages unchangeable.

---

# PART 15 — `pip list` VS `pip freeze`

## 22. Understand the Difference

### `pip list`

```cmd
python -m pip list
```

Primarily for **viewing installed packages** in a readable table.

### `pip freeze`

```cmd
python -m pip freeze
```

Primarily for **capturing installed packages and exact versions** in a requirements-friendly format.

Simple way to remember:

```text
pip list
   ↓
Look at packages

pip freeze
   ↓
Capture packages + versions
```

# PART 16 — INSTALL FROM `requirements.txt`

## 23. Why Is This Important?

Suppose another student downloads CampusQuest.

They do not need to install every package manually.

They can create a new environment:

```cmd
python -m venv venv
```

Activate it:

```cmd
venv\Scripts\activate
```

Then install everything:

```cmd
python -m pip install -r requirements.txt
```

The flow is:

```text
requirements.txt
       ↓
Create venv
       ↓
Activate venv
       ↓
pip install -r requirements.txt
       ↓
Dependencies installed
       ↓
Project environment ready
```

This is an important professional development workflow.

## 25. What Does Deactivate Do?

Deactivation does **not** delete the environment.

It simply stops using that virtual environment in the current Command Prompt session.

```text
activate
   ↓
Use venv

deactivate
   ↓
Stop using venv
```

The `venv` folder remains on disk.

# PART 19 — DELETE AND RECREATE `venv`

## 27. Delete a Virtual Environment

If an environment becomes corrupted or you simply want a fresh one:

First deactivate:

```cmd
deactivate
```

Then:

```cmd
rmdir /s /q venv
```

> ⚠️ This permanently deletes the `venv` directory and everything inside it.

For beginners, you can also delete the `venv` folder using File Explorer.

---

## 28. Recreate It

Create it again:

```cmd
python -m venv venv
```

Activate:

```cmd
venv\Scripts\activate
```

Your packages will need to be installed again.

Or, if `requirements.txt` already exists:

```cmd
python -m pip install -r requirements.txt
```

This is one reason `requirements.txt` is useful.

# PART 20 — `venv` VS CONDA

## 29. What Is Anaconda?

Anaconda is a Python distribution commonly used for:

- Data science
- Scientific computing
- Machine learning
- Analytics
- Jupyter workflows

It comes with tools for managing environments and packages.

---

## 30. What Is Conda?

Conda is an environment and package manager.

For example:

```cmd
conda create -n campusquest python
```

Activate:

```cmd
conda activate campusquest
```

Deactivate:

```cmd
conda deactivate
```

List Conda environments:

```cmd
conda env list
```

Notice something important:

```cmd
conda env list
```

exists for Conda.

Standard Python `venv` does **not** have an equivalent central environment-list command.

---

# PART 21 — `venv` VS CONDA

| Feature | Python `venv` | Conda |
|---|---|---|
| Included with standard Python | Yes | No |
| Creates isolated environments | Yes | Yes |
| Package manager | pip | conda and/or pip |
| Non-Python dependencies | Limited | Strong |
| Django projects | Excellent | Possible |
| Data science | Basic | Excellent |
| Separate installation | No | Yes |
| Simple for Django beginners | Yes | More tooling |
| Central environment list | No | Yes |

For **CampusQuest**, use:

```text
Python
   ↓
venv
   ↓
pip
   ↓
Django packages
```

Do not unnecessarily combine:

```text
Conda
   +
venv
   +
global pip
```

Keep the environment setup simple.
