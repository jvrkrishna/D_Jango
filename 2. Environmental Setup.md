# PART A — UNDERSTANDING PYTHON ENVIRONMENTS

## 1. What Is a Python Environment?

Before learning Django, students must understand:

> **Where are Python and Python packages installed?**

If Python is installed on a computer, it is available through the system/global Python installation.

```text
Windows Computer
│
└── Python
    │
    ├── pip
    ├── Django
    ├── requests
    └── other packages
```

---

## 2. The Problem With Global Packages

Imagine we have two projects:

```text
Project A
Needs Django version A

Project B
Needs Django version B
```

If both projects use the same global Python environment, package changes can affect other projects.

This can create:

> **Dependency conflicts**

---

## 3. Solution — Virtual Environments

Instead, each project can have its own isolated environment.

```text
Computer
│
├── Global Python
│
├── CampusQuest
│   └── venv
│
└── AnotherProject
    └── venv
```

For CampusQuest:

```text
CampusQuest
│
└── venv
    ├── Django
    ├── Django REST Framework
    ├── psycopg
    └── python-dotenv
```

> **A virtual environment isolates a project's Python dependencies from other projects and the system Python installation.**

---

## 4. Simple Student Analogy

Imagine every student has a separate toolbox:

```text
Student A
└── Toolbox

Student B
└── Toolbox

Student C
└── Toolbox
```

Changing Student A's tools does not affect Student B.

A Python virtual environment works similarly.

> **One project = one isolated Python environment**

---

## 5. What Is `venv`?

Python provides a built-in module called:

```text
venv
```

It creates virtual environments.

Command:

```cmd
python -m venv venv
```

Explanation:

```text
python
```

Use Python.

```text
-m
```

Run a Python module.

```text
venv
```

Python's built-in virtual-environment module.

The final:

```text
venv
```

is the name of the environment folder.

---

## 6. Environment Name Can Be Anything

For example:

```cmd
python -m venv myenv
```

creates:

```text
myenv/
```

Or:

```cmd
python -m venv django_env
```

creates:

```text
django_env/
```

For CampusQuest we will use the common convention:

```text
venv
```

Open **Command Prompt**.

Navigate to the project folder:

```cmd
cd C:\Projects\CampusQuest
```

```cmd
python -m venv venv
```

After the command:

```text
CampusQuest
```

---

# 9. What Is Inside `venv`?

On Windows, you will normally see:

```text
venv
│
├── Include
├── Lib
├── Scripts
└── pyvenv.cfg
```

The important folder for Windows is:

```text
Scripts
```

It contains the executables and activation scripts for the environment.

---

# 10. How Do We Know the Environment Exists?

There is no standard command such as:

```cmd
python list environments
```

for Python's built-in `venv`.

Instead, inspect the folder:

```cmd
dir
```

You should see:

```text
venv
```

You can also inspect:

```cmd
dir venv
```

and:

```cmd
dir venv\Scripts
```

---

# 11. Important: Python `venv` Does Not Have a Global Environment List

With standard Python `venv`, there is no central registry containing every environment on your computer.

For example:

```text
C:\Projects\CampusQuest\venv
C:\Projects\CollegeApp\venv
D:\PythonProjects\ShopApp\venv
```

Python does not automatically provide:

```cmd
python --list-environments
```

You normally locate environments by their directories.

This is different from environment managers such as Conda.

---

# 12. Activate the Environment

Creating an environment does **not** automatically activate it.

From the project directory:

```cmd
venv\Scripts\activate
```

After activation:

```text
(venv) C:\Projects\CampusQuest>
```

The important part is:

```text
(venv)
```

---

# 13. What Does Activation Mean?

Activation configures the current Command Prompt session so that Python and package commands use the virtual environment.

Before activation:

```text
python
   ↓
Global/System Python
```

After activation:

```text
python
   ↓
CampusQuest\venv Python
```

---

```cmd

```

You may see something similar to:

```text
C:\Projects\CampusQuest\venv\Scripts\python.exe
C:\Users\Student\AppData\Local\Programs\Python\Python...\python.exe
```

The virtual environment Python should appear first.

---

# 20. Deactivate the Environment

Run:

```cmd
deactivate
```

The prompt changes from:

```text
(venv) C:\Projects\CampusQuest>
```

to:

```text
C:\Projects\CampusQuest>
```

The `(venv)` disappears.

---

# 21. What Does Deactivate Mean?

Deactivation does **not** delete the environment.

It only stops using the environment in the current Command Prompt session.

```text
Activate
   ↓
Start using environment

Deactivate
   ↓
Stop using environment
```

The environment remains on disk.

---

# 22. Activate Again

After deactivation:

```cmd
venv\Scripts\activate
```

You will see:

```text
(venv) C:\Projects\CampusQuest>
```

---

# 23. Delete a Virtual Environment

First deactivate it:

```cmd
deactivate
```

Then delete the folder:

```cmd
rmdir /s /q venv
```

⚠️ `rmdir /s /q` permanently deletes the directory and its contents without asking for confirmation.

For beginners, deleting the `venv` folder through File Explorer is also fine.

---

# 24. Recreate a Virtual Environment

After deleting:

```cmd
python -m venv venv
```

Then:

```cmd
venv\Scripts\activate
```

This creates a fresh environment.

Packages such as Django must be installed again.

---

# 25. Restore an Environment From requirements.txt

If a project has:

```text
requirements.txt
```

we can recreate the environment:

```cmd
python -m venv venv
```

Activate:

```cmd
venv\Scripts\activate
```

Install dependencies:

```cmd
python -m pip install -r requirements.txt
```

Flow:

```text
requirements.txt
       ↓
Create venv
       ↓
Activate
       ↓
pip install -r requirements.txt
       ↓
Environment restored
```

# PART A.1 — PYTHON `venv` vs ANACONDA / CONDA

# 29. What Is Anaconda?

Anaconda is a Python distribution commonly used for:

- Data science
- Scientific computing
- Machine learning
- Analytics
- Jupyter-based workflows

It includes tools for managing environments and packages.

---

# 30. What Is Conda?

Conda is an environment and package management system.

It can create isolated environments.

Example:

```cmd
conda create -n campusquest python
```

Activate:

```cmd
conda activate campusquest
```

Deactivate:

```cmd
conda deactivate
```

List Conda environments:

```cmd
conda env list
```

---

# 31. `venv` vs Conda

| Feature | Python `venv` | Conda |
|---|---|---|
| Included with standard Python | Yes | No |
| Creates isolated environments | Yes | Yes |
| Package manager | Usually pip | conda and/or pip |
| Manages non-Python dependencies | Limited | Strong |
| Django projects | Excellent | Possible |
| Data science ecosystem | Basic | Excellent |
| Requires separate installation | No | Yes |
| Simple for Django beginners | Yes | More tooling |

---

# 32. Which One Will We Use?

For CampusQuest:

> **We will use Python's built-in `venv`.**

Our stack:

```text
Python
   ↓
venv
   ↓
pip
   ↓
Django
   ↓
Django REST Framework
   ↓
PostgreSQL
```

Why?

- Simple
- Built into Python
- Lightweight
- Easy for beginners
- Common for web development
- No additional environment manager required

---

# 33. Environment Listing Difference

Conda maintains an environment registry:

```cmd
conda env list
```

Standard Python `venv` does not maintain a central environment registry.

For `venv`, locate environments through their folders.

---

# 34. Do Not Mix Environment Managers Without a Reason

Avoid unnecessarily doing:

```text
Conda environment
      +
venv inside Conda
      +
global pip packages
```

For this course:

```text
Python
  ↓
venv
  ↓
pip
  ↓
Django packages
```

Keep it simple.

## Q1. What is a virtual environment?

A virtual environment is an isolated Python environment that keeps a project's dependencies separate from other projects and the system Python installation.

## Q2. How do you create one?

```cmd

```

## Q3. How do you activate it on Windows CMD?

```cmd
venv\Scripts\activate
```

## Q4. How do you deactivate it?

```cmd
deactivate
```

## Q5. Does deactivation delete the environment?

No. It only stops using the environment in the current terminal session.

## Q6. How do you delete a virtual environment?

First:

```cmd
deactivate
```

Then:

```cmd
rmdir /s /q venv
```

## Q7. How do you recreate it?

```cmd
python -m venv venv
```

## Q8. Can standard Python list all `venv` environments?

No. Standard `venv` does not maintain a central environment registry. Environments are normally found by their directories.

## Q9. What is Conda?

Conda is an environment and package management system that can manage Python environments and other dependencies.

## Q10. Which environment system will we use for CampusQuest?

It is simple, lightweight, built into Python, and well suited for our Django project.
