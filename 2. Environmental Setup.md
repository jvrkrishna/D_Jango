# Day 2 — Python Virtual Environments & Django Installation

## 1. Why Do We Need a Virtual Environment?

Before installing Django, we need to understand an important problem.

A computer can have Python installed globally:

```text
Windows
   │
   └── Python
       ├── pip
       ├── Django
       ├── requests
       └── other packages
```

Suppose we have two different projects:

```text
Project A → Django 5.x

Project B → Django 4.x
```

If both projects use the same global Python environment, installing or upgrading packages for one project can affect the other project.

This can create **dependency conflicts**.

### Solution

Create a separate virtual environment for each project:

```text
Computer
│
├── Global Python
│
├── Project A
│   └── venv
│
└── Project B
    └── venv
```

> **A virtual environment provides an isolated Python environment for a project and its dependencies.**

---

# 2. What Is `venv`?

Python provides a built-in module called:

```text
venv
```

It is used to create virtual environments.

The basic command is:

```cmd
python -m venv venv
```

Understand the command:

```text
python
   ↓
Run Python

-m
   ↓
Run a Python module

venv
   ↓
Python's virtual-environment module

venv
   ↓
Name of the environment folder
```

The last `venv` is simply the folder name.

We could also use:

```cmd
python -m venv myenv
```

or:

```cmd
python -m venv django_env
```

For this course, we will use:

```text
venv
```

---

# 5. What Is Inside `venv`?

Run:

```cmd
dir venv
```

You will normally see folders/files similar to:

```text
venv
│
├── Include
├── Lib
├── Scripts
└── pyvenv.cfg
```

The important folder on Windows is:

```text
Scripts
```

It contains the environment's Python executable and activation scripts.

---

# 6. Creating vs Activating a Virtual Environment

These are two different operations.

### Creating

```cmd
python -m venv venv
```

This **creates** the environment.

### Activating

```cmd
venv\Scripts\activate
```

This **activates** the environment for the current Command Prompt session.

After activation, the command prompt should look similar to:

```text
(venv) C:\Users\<username>\Desktop\myproject>
```

The important part is:

```text
(venv)
```

---

# 7. What Does Activation Do?

Activation makes the current command-line session use the virtual environment's Python and package tools.

### Before activation

```text
python
   ↓
Global Python
```

### After activation

```text
python
   ↓
venv Python
```

Therefore, when we install Django after activating the environment, Django will be installed into that project's environment.

---

# 8. Verify Which Python Is Being Used

After activating the environment, run:

```cmd
where python
```

You should see the virtual environment's Python first.

For example:

```text
C:\Users\<username>\Desktop\myproject\venv\Scripts\python.exe
```

You may also see your normal Python installation afterward.

The important point is:

> **The virtual environment's Python should appear first.**

# 9. Check Python Version

Run:

```cmd
python --version
```

Example:

```text
Python 3.x.x
```

The exact version depends on the Python installation.

---

# 10. What Is `pip`?

`pip` is Python's package installer.

It is used to install and manage Python packages.

For example:

```cmd
python -m pip install django
```

Instead of simply using:

```cmd
pip install django
```

we will generally use:

```cmd
python -m pip
```

This makes it clear that `pip` is being run through the Python interpreter currently being used.

---

# 11. Check `pip`

Run:

```cmd
python -m pip --version
```

The output should point to the active virtual environment.

For example:

```text
pip ... from ...\myproject\venv\Lib\site-packages\pip
```

This confirms that the environment's package manager is being used.

---

# 12. Check Installed Packages

Run:

```cmd
python -m pip list
```

A newly created virtual environment contains only a small set of packages.

Packages installed globally on the computer are not automatically copied into the new virtual environment.

This is the isolation provided by the virtual environment.

---

# 13. Upgrade `pip`

Before installing Django, upgrade pip:

```cmd
python -m pip install --upgrade pip
```

This updates pip inside the active virtual environment.

---

# 14. Install Django

Now install Django:

```cmd
python -m pip install django
```

Because `(venv)` is active, Django is installed into the virtual environment.

The relationship is:

```text
Project
   │
   └── venv
       │
       └── Django
```

---

# 17. What Is a Dependency?

A **dependency** is a package that another package requires to work properly.

For example:

```text
Django
  │
  ├── asgiref
  ├── sqlparse
  └── other dependencies
```

When Django is installed, pip automatically installs the packages Django needs.

---

# 18. What Is `requirements.txt`?

A project usually needs a record of its Python dependencies.

That record is commonly stored in:

```text
requirements.txt
```

For example:

```text
Django==5.x.x
```

If a project has multiple packages, it might contain:

```text
Django==5.x.x
some-package==1.x.x
another-package==2.x.x
```

This allows the same dependencies to be installed in another environment.

---

# 19. What Is `pip freeze`?

Run:

```cmd
python -m pip freeze
```

It displays installed Python packages and their versions.

For example:

```text
Django==5.x.x
asgiref==...
sqlparse==...
tzdata==...
```

`pip freeze` does not freeze Python.

It simply outputs the installed packages and their versions in a requirements-friendly format.

---

# 20. Create `requirements.txt`

Run:

```cmd
python -m pip freeze > requirements.txt
```

The `>` redirects the output into a file.

Conceptually:

```text
python
   ↓
pip freeze
   ↓
Installed packages + versions
   ↓
requirements.txt
```

The project now looks like:

```text
myproject
│
├── venv
│
└── requirements.txt
```

---

# 21. View `requirements.txt`

To display the file in Command Prompt:

```cmd
type requirements.txt
```

You may see:

```text
Django==5.x.x
asgiref==...
sqlparse==...
tzdata==...
```

The exact versions depend on the installed packages.

---

# 22. `pip list` vs `pip freeze`

### `pip list`

```cmd
python -m pip list
```

Used mainly to view installed packages in a readable table.

### `pip freeze`

```cmd
python -m pip freeze
```

Used mainly to output installed packages with exact versions.

Simple distinction:

```text
pip list
    ↓
View installed packages

pip freeze
    ↓
Capture installed packages + versions
```

---

# 23. Install Dependencies from `requirements.txt`

Suppose another developer receives the project.

They can create a new virtual environment:

```cmd
python -m venv venv
```

Activate it:

```cmd
venv\Scripts\activate
```

Then install the project's dependencies:

```cmd
python -m pip install -r requirements.txt
```

The flow is:

```text
requirements.txt
       ↓
Create virtual environment
       ↓
Activate environment
       ↓
pip install -r requirements.txt
       ↓
Dependencies installed
```

This is a common Python project workflow.

---

# 24. Deactivate the Virtual Environment

To leave the active virtual environment:

```cmd
deactivate
```

The prompt changes from:

```text
(venv) C:\Users\<username>\Desktop\myproject>
```

to:

```text
C:\Users\<username>\Desktop\myproject>
```

The `(venv)` disappears.

---

# 25. What Does `deactivate` Do?

`deactivate` does **not** delete the virtual environment.

It only stops using that virtual environment in the current Command Prompt session.

```text
activate
   ↓
Use virtual environment

deactivate
   ↓
Stop using virtual environment
```

The `venv` folder remains on the computer.

---

# 26. Activate an Existing Environment Again

If the environment already exists, activate it with:

```cmd
venv\Scripts\activate
```

The prompt should again show:

```text
(venv)
```

You can then use:

```cmd
python
```

and:

```cmd
python -m pip
```

from that environment.

---

# 27. Delete a Virtual Environment

A virtual environment is a directory containing the environment files.

First deactivate it:

```cmd
deactivate
```

Then delete the folder:

```cmd
rmdir /s /q venv
```

This permanently removes the `venv` directory.

The project source files outside `venv` are not deleted.

---

# 28. Recreate the Virtual Environment

Create it again:

```cmd
python -m venv venv
```

Activate it:

```cmd
venv\Scripts\activate
```

Then install the dependencies:

```cmd
python -m pip install -r requirements.txt
```

This recreates the Python environment from the dependency file.

---

# 29. `venv` vs Conda

Python provides `venv` as part of the standard Python installation.

Conda is another environment and package-management system.

### Python `venv`

```text
Python
  ↓
venv
  ↓
pip
  ↓
Django
```

### Conda

```text
Conda
  ↓
Environment
  ↓
Packages
```

For this Django course, we will use:

```text
Python
   ↓
venv
   ↓
pip
   ↓
Django
```

There is no need to use Conda for this setup.
