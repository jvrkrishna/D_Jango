# 18. What Happens When We Open a Website?

Suppose we open:

```text
https://example.com/products/
```

A simplified process is:

```text
1. User enters URL
        ↓
2. Browser interprets URL
        ↓
3. DNS helps resolve the domain
        ↓
4. Browser connects to the server
        ↓
5. Browser sends HTTP/HTTPS request
        ↓
6. Server receives request
        ↓
7. Web application processes request
        ↓
8. Application may access database
        ↓
9. Server creates response
        ↓
10. Browser receives response
        ↓
11. Browser renders the page
```

This request-response cycle is fundamental to web development.

# 21. What Is HTTP?

HTTP stands for:

> **HyperText Transfer Protocol**

HTTP is a protocol used for communication between clients and servers.

Basic communication:

```text
Client
   |
   | HTTP Request
   v
Server
   |
   | HTTP Response
   v
Client
```

HTTP is **stateless** by design.

This means each request is treated independently unless additional mechanisms such as cookies or sessions are used to maintain state.

---

# 22. What Is HTTPS?

HTTPS stands for:

> **HyperText Transfer Protocol Secure**

HTTPS uses TLS to protect communication between the client and server.

```text
HTTP
↓
Data transferred without transport encryption

HTTPS
↓
HTTP + TLS protection
```

HTTPS helps protect against threats such as unauthorized interception of data during transmission.

Modern production websites should generally use HTTPS.

# 30. Authentication vs Authorization

These two terms are commonly confused.

## Authentication

Authentication answers:

> **Who are you?**

Example:

```text
Email + Password
        ↓
Identity verified
```

## Authorization

Authorization answers:

> **What are you allowed to do?**

Example:

```text
User logged in
      ↓
Is this user an administrator?
      ↓
Yes → Allow admin operation
No  → Deny access
```

Easy way to remember:

```text
Authentication = Who are you?

Authorization = What can you do?
```

Django provides authentication-related functionality and tools for controlling access.

# 34. What Is SQL?

SQL stands for:

> **Structured Query Language**

Example:

```sql

```

This retrieves records from a database table.

Another example:

```sql

```

Django can generate appropriate SQL through its ORM.

# 35. What Is ORM?

ORM stands for:

> **Object-Relational Mapping**

Django includes an ORM that allows developers to interact with database data using Python.

Instead of manually writing SQL for every operation, we can use Django ORM expressions.

Example:

```python
Student.objects.all()
```

Another example:

```python
Student.objects.filter(points__gt=500)
```

The ORM translates these operations into database queries.

# 40. Framework vs Library

This is an important interview concept.

## Library

A library is a collection of reusable code that your application calls when needed.

Conceptually:

```text
Your Application
       |
       | calls
       v
    Library
```

## Framework

A framework provides an overall structure in which your application runs.

Conceptually:

```text
Framework
   |
   +-- Your Application
   |
   +-- Your Code
   |
   +-- Framework Components
```

A commonly used explanation is:

> **With a library, your code calls the library. With a framework, the framework often calls your code at appropriate points.**

This idea is sometimes called **Inversion of Control**.

# 45. Django vs Flask

Both are Python web frameworks.

| Django                                     | Flask                                     |
| ------------------------------------------ | ----------------------------------------- |
| More batteries-included                    | More minimal                              |
| Includes ORM ecosystem                     | Database tools can be selected separately |
| Built-in admin                             | No built-in admin equivalent              |
| Built-in authentication tools              | Usually assembled with extensions         |
| Strong project conventions                 | More freedom in structure                 |
| Suitable for large structured applications | Good for small services and applications  |
| More functionality included by default     | Developers choose more components         |

### When Django is attractive

Django is especially useful when an application needs many standard web features and you want a well-defined structure.

Flask can be attractive when you want a smaller core and greater freedom in selecting components.

# 58. Django and MVC

Many web frameworks use the MVC pattern:

```text
M → Model
V → View
C → Controller
```

Django is commonly described as MVT:

```text
M → Model
V → View
T → Template
```

The concepts are related, but the naming and responsibilities are not identical.

A useful comparison:

```text
Traditional MVC

Model       → Data
View        → Presentation
Controller  → Request/Application flow


Django MVT

Model       → Data
Template    → Presentation
View        → Request/Application logic
```

In Django, the framework itself handles much of the controller-like request dispatching behavior.

Therefore, do not memorize:

> "Django View = exactly MVC Controller."

Instead understand the responsibilities.

# 61. Project vs App

| Project                         | App                                  |
| ------------------------------- | ------------------------------------ |
| Overall Django site/application | Specific functionality               |
| Contains configuration          | Contains feature-specific code       |
| Can contain multiple apps       | Belongs to a project                 |
| Defines project settings        | Implements application functionality |

Easy way to remember:

> **Project = whole system**

> **App = one functional component**

# 64. What Is WSGI?

WSGI stands for:

> **Web Server Gateway Interface**

WSGI is a standard interface between Python web applications and compatible web servers.

Django can be deployed using WSGI-compatible servers.

Conceptually:

```text
Web Server
     |
     | WSGI
     v
Django Application
```

WSGI is traditionally associated with synchronous Python web applications.

---

# 65. What Is ASGI?

ASGI stands for:

> **Asynchronous Server Gateway Interface**

ASGI is a newer interface designed to support asynchronous Python applications and communication patterns.

Django supports ASGI.

Conceptually:

```text
Web Server
     |
     | ASGI
     v
Django Application
```

ASGI is useful when applications need asynchronous capabilities.

Students do not need to master WSGI/ASGI on Day 1.

The important point is:

> Django can run behind production server infrastructure through interfaces such as WSGI and ASGI.

# 77. Limitations of Django

Django is powerful, but it is not perfect for every situation.

Possible disadvantages include:

### Larger framework

For a tiny service, Django may provide more functionality than needed.

### Opinionated structure

Django encourages certain conventions and patterns.

Some developers may prefer more freedom.

### Learning curve

Django has many concepts:

```text

Templates
Models
ORM
Forms
Admin

Migrations
```

Beginners need time to understand how these components work together.

If the only requirement is a small API service, an API-focused framework such as FastAPI may sometimes be a better fit.

# 79. When Might Django Not Be the Best Choice?

Django may not be the ideal choice when:

* You need an extremely small service
* You want a minimal framework
* Your team is entirely specialized in another ecosystem
* The application has highly specialized requirements better served by another technology
* You need a very small API and do not need Django's broader features

The correct question is not:

> "Which framework is the best?"

The better question is:

> **"Which framework is the best fit for this project's requirements?"**

# 82. Day 1 Important Definitions

### Internet

A global network of interconnected computer systems.

### Web

A system of interconnected resources accessed over the Internet, primarily through HTTP/HTTPS.

### Website

A collection of web pages and resources.

### Web Application

Software accessed and used through a web browser.

### Frontend

The user-facing portion of an application.

### Backend

The server-side portion responsible for processing and application logic.

### Client

Software that sends requests.

### Server

A system that receives requests and provides services or responses.

### URL

A Uniform Resource Locator that identifies a resource.

### DNS

The Domain Name System that maps domain names to IP addresses.

### HTTP

A protocol used for communication between clients and servers.

### HTTPS

HTTP protected by TLS.

### Database

A system for storing and managing data.

### SQL

A language commonly used to work with relational databases.

### ORM

Object-Relational Mapping, which provides an abstraction for working with database data.

### API

An interface through which software systems communicate.

### Framework

A structured software foundation that provides reusable tools, conventions, and functionality for building applications.

### Django

A high-level Python web framework for building web applications.

### Model

Django's representation of application data and database structure.

### View

Django code that processes a request and produces a response.

### Template

A mechanism for generating HTML from data.

### Middleware

Components that process requests and responses as they pass through Django.
