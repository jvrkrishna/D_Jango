# 1. What Is a Website?

A website is a collection of web pages that users access through a web browser.

Examples:

* College website
* Company website
* News website
* Blog
* Documentation website

A website can contain:

```text
Home
About
Services
Contact
```

---

# 2. What Is a Web Application?

A web application is software that users interact with through a web browser.

A web application can:

* Accept user input
* Process data
* Store data
* Retrieve data
* Authenticate users
* Perform business logic
* Communicate with a database

Examples:

* Online banking
* E-commerce
* Student portals
* Learning management systems
* Social media applications

### Simple Difference

```text
Website
→ Mainly presents information

Web Application
→ Provides interactive functionality
```

# 4. Client and Server

## Client

The client is the software that sends a request.

Examples:

* Chrome
* Firefox
* Edge
* Mobile application

## Server

The server receives the request, processes it, and sends a response.

```text
Client
Browser
   |
   | Request
   v
Server
Django
   |
   | Response
   v
Client
Browser
```

Remember:

> **Client sends the request. Server processes the request and sends the response.**

---

# 5. Request and Response

This is one of the most important concepts students should understand before Django.

### Request

A request is a message sent from the client to the server.

Example:

```text
GET /products/
```

Meaning:

> "Give me the products page/data."

### Response

A response is the message sent from the server back to the client.

Example:

```text
200 OK
```

The response may contain:

* HTML
* JSON
* Images
* Files
* Error information

Basic flow:

```text
Browser
   |
   | Request
   v
Django
   |
   | Response
   v
Browser
```

# 6. What Is HTTP?

HTTP stands for:

> **HyperText Transfer Protocol**

HTTP is the protocol used for communication between clients and web servers.

```text
Browser
   |
   | HTTP Request
   v
Server
   |
   | HTTP Response
   v
Browser
```

Students only need to understand the basic HTTP methods at this stage.

| Method | Purpose               |
| ------ | --------------------- |
| GET    | Get data              |
| POST   | Send/create data      |
| PUT    | Update/replace data   |
| PATCH  | Partially update data |
| DELETE | Delete data           |

We will study these in detail later when working with Django and APIs.

---

# 7. What Is a URL?

URL stands for:

> **Uniform Resource Locator**

A URL identifies a resource on the Web.

Example:

```text
https://example.com/products/
```

For Django, the important part students should understand is the **path**:

```text
/products/
```

Django will use URL patterns to decide which view should handle a request.

For example:

```text
/products/
     ↓
Product View
```

We will study Django URL routing in detail later.

# 10. What Is a Framework?

A framework is a pre-built software structure that provides tools, conventions, and reusable functionality for building applications.

Imagine building a house.

Without a framework:

```text
Build everything yourself
        ↓
More work
        ↓
More complexity
        ↓
More chances for mistakes
```

With a framework:

```text
Framework provides foundation
        ↓
Developer adds application functionality
```

A web framework can provide:

* URL routing
* Request handling
* Database integration
* Authentication
* Forms
* Security
* Templates
* Testing
* Application structure

---

# 11. Why Use a Framework?

Without a framework, developers would repeatedly need to build common functionality.

For example:

```text
URL Routing
Request Handling
Database Communication
Authentication
Forms
Validation
Security
Sessions
```

A framework provides established solutions for these common problems.

Therefore:

> **A framework helps developers build applications faster, more consistently, and with a structured architecture.**

# 12. What Is Django?

Django is a:

> **High-level Python web framework for building web applications.**

Remember:

```text
Python
```

```text
Python = Programming Language

Django = Python Web Framework
```

---

# 14. Why Django Instead of Other Frameworks?

There is no single framework that is best for every project.

Different frameworks have different strengths.

| Framework    | Language   | General Strength                 |
| ------------ | ---------- | -------------------------------- |
| Django       | Python     | Full-featured web applications   |
| Flask        | Python     | Lightweight and flexible         |
| FastAPI      | Python     | API-focused applications         |
| Spring Boot  | Java       | Enterprise applications          |
| ASP.NET Core | C#         | Microsoft/.NET applications      |
| Laravel      | PHP        | PHP web applications             |
| Express      | JavaScript | Lightweight Node.js applications |

### Why choose Django?

Django is a strong choice when you want:

* Python
* Rapid development
* Built-in functionality
* Database-driven applications
* Authentication
* Admin interface
* Forms
* ORM
* Strong project structure
* Security features
* Server-rendered web applications
* API development through Django REST Framework

The important point is:

> **We don't choose Django because it is universally the best framework. We choose it because it provides a strong set of features for the type of applications we want to build.**

# 16. Django Architecture — MVT

Django is commonly taught using:

> **MVT — Model, View, Template**

```text
M = Model
V = View
T = Template
```

Each component has a different responsibility.

---

# 17. Model

A **Model** represents application data.

For example:

```text
Student
----------------
id
name
email
department
```

The model works with the database through Django's ORM.

Remember:

> **Model = Data**

---

# 18. View

A **View** handles a request and produces a response.

A view may:

* Receive request data
* Perform application logic
* Query the database
* Validate information
* Return HTML
* Return JSON
* Redirect the user

Remember:

> **View = Logic / Request Handling**

---

# 19. Template

A **Template** is used to create the HTML shown to the user.

Example:

```html
<h1>Welcome, {{ name }}</h1>
```

If:

```text
name = "Ravi"
```

the browser can display:

```text
Welcome, Ravi
```

Remember:

> **Template = Presentation**

# 21. Django Project vs Django App

This is an important concept before starting practical Django.

## Project

The Django project represents the overall website/application.

Example:

```text
myproject
```

## App

A Django app contains a particular area of functionality.

Examples:

```text
accounts
products
orders
blog
payments
```

A project can contain multiple apps:

```text
Project
   |
   +-- accounts
   +-- products
   +-- orders
   +-- payments
```

Remember:

> **Project = Whole application**

> **App = Specific functionality**
