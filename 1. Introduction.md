* HTTP/HTTPS
* Web browsers
* Web servers
* HTML
* CSS
* JavaScript
* Databases
* APIs

```text

   |

   v

   |
   v

   |
   v
```

Django operates mainly on the **server side** of this system.

# 3. What Is a Website?

A website is a collection of web pages and resources that users can access through a web browser.

Examples:

* College website
* Company website
* News website
* Documentation website
* Wikipedia
* Portfolio website

A simple college website might contain:


The important point is:

> A website presents information or functionality to users through web pages and other web resources.

A website can be simple or highly interactive.

# 4. What Is a Web Application?

A **web application** is software that users interact with through a web browser.

A web application generally contains functionality such as:

* User registration
* Login
* Forms
* Data storage
* Search
* Dashboards
* Authentication
* Authorization
* Business logic
* CRUD operations
* Payments
* Notifications
* APIs

Examples:

* Online banking
* E-commerce applications
* Learning management systems
* Social media platforms
* College portals
* Project management systems

---

# 5. Website vs Web Application

| Website                                | Web Application                          |
| -------------------------------------- | ---------------------------------------- |
| Primarily provides information/content | Provides interactive functionality       |
| May have limited user interaction      | Usually has significant user interaction |
| Often content-focused                  | Usually functionality/data-focused       |
| Users may mostly consume information   | Users can create or modify data          |
| Example: College information site      | Example: Student portal                  |
| Backend may be simple or complex       | Usually requires application logic       |

### Important

The distinction is not absolute.

A modern website can contain highly interactive features, and a web application also contains web pages.

The useful beginner distinction is:

> **A website mainly presents content, while a web application provides software functionality through the web.**

# 11. What Happens When We Open a Website?

Suppose a student enters:

```text
https://campusquest.com/challenges/
```

A simplified version of what happens is:

```text
1. User enters URL
        ↓
2. Browser prepares a request
        ↓
3. Request travels to the server
        ↓
4. Web server/application receives request
        ↓
5. Django processes the request
        ↓
6. Django may communicate with database
        ↓
7. Django creates a response
        ↓
8. Browser receives response
        ↓
9. Browser renders the result
```

This is the foundation of web development.

# 12. Request and Response

The communication between a client and server is based on **requests and responses**.

```text
Client
   |
   | HTTP Request
   v
Server
   |
   | HTTP Response
   v
Client
```

---

## 12.1 What Is a Request?

A **request** is a message sent by a client to a server.

For example:

```http
GET /challenges/
```

Conceptually, the browser is saying:

> "Please give me the challenges resource."

A request can contain information such as:

* HTTP method
* URL/path
* Headers
* Query parameters
* Request body
* Cookies

---

# 13. What Is a Response?

A **response** is the message returned by the server.

For example:

```http
HTTP/1.1 200 OK
```

The response may contain:

* HTML
* JSON
* Images
* CSS
* JavaScript
* Files
* Error information

Example:

```text
Browser
   |
   | GET /challenges/
   v
Django
   |
   v
Database
   |
   v
Django
   |
   | HTML Response
   v

```

# 14. What Is HTTP?

HTTP stands for:

> **HyperText Transfer Protocol**

HTTP is a protocol used for communication between clients and servers on the web.

Basic flow:

```text
Client
   |
   | HTTP Request
   v
Server
   |
   | HTTP Response
   v
Client
```

When HTTPS is used, the communication is protected using encryption.

---

# 15. HTTP Request Example

A simplified request might look like:

```http
GET /challenges/ HTTP/1.1
Host: campusquest.com
```

Students do not normally type this manually.

The browser creates the request.

---

# 16. HTTP Methods

HTTP defines methods that indicate what operation the client wants to perform.

| Method | Common Meaning              |
| ------ | --------------------------- |
| GET    | Retrieve data               |
| POST   | Submit/create data          |
| PUT    | Replace/update a resource   |
| PATCH  | Partially update a resource |
| DELETE | Delete a resource           |

### CampusQuest examples

```text
GET
→ Display challenges

POST
→ Submit a challenge attempt

PUT
→ Replace a student's profile data

PATCH
→ Update only the student's department

DELETE
→ Delete a challenge
```

### Important

The HTTP method describes the intended operation.

The actual behavior depends on how the application implements the endpoint.

---

# 17. HTTP Status Codes

When a server sends a response, it also provides a **status code**.

Status codes are grouped into categories.

| Range | Meaning           |
| ----- | ----------------- |
| 1xx   | Informational     |
| 2xx   | Successful        |
| 3xx   | Redirection       |
| 4xx   | Client-side error |
| 5xx   | Server-side error |

Important examples:

| Code    | Meaning               |
| ------- | --------------------- |
| 200     | OK                    |
| 201     | Created               |
| 204     | No Content            |
| 301/302 | Redirection           |
| 400     | Bad Request           |
| 401     | Unauthorized          |
| 403     | Forbidden             |
| 404     | Not Found             |
| 500     | Internal Server Error |

For example:

```text
GET /challenges/

        ↓

200 OK
```

means the request was successfully processed.

# 19. Why Do We Need a Database?

Imagine 10,000 students using CampusQuest.

We cannot store all their information inside Python variables:

```python
students = [...]
```

Variables are temporary application memory.

We need persistent storage.

A database allows us to store data so that it can be:

* Created
* Retrieved
* Updated
* Deleted
* Searched
* Related
* Persisted

Django provides tools that make database interaction much easier.

---

# 20. What Is an ORM?

ORM stands for:

> **Object-Relational Mapping**

Django provides an ORM that allows developers to interact with databases using Python objects and query expressions instead of writing SQL for every operation.

For example, conceptually:

```python
Student.objects.all()
```

means:

> "Give me all Student records."

Later we will learn:

```python
Student.objects.filter(points__gte=500)
```

This can be used to find students with at least 500 points.

The ORM is one of Django's most important features.

# 25. What Is Django?

> **Django is a high-level Python web framework for building secure and maintainable web applications efficiently.**

Let's understand the important words.

### Python

Django is written in Python and applications are developed using Python.

### Web Framework

Django provides tools and structures for building web applications.

### High-Level

Django handles many common web-development tasks for us.

Django includes security features and secure defaults that help developers avoid common web vulnerabilities.

### Maintainable

Django encourages organized application structure and reusable components.

# 28. Django Philosophy

Django follows a philosophy of:

> **Don't Repeat Yourself (DRY)**

Django also emphasizes:

* Reusability
* Maintainability
* Security
* Convention
* Rapid development

# 31. View

A Django **View** receives a request and contains the application logic needed to produce a response.

For example:

```text
Student requests:

/leaderboard/

       ↓

URL routing

       ↓

Leaderboard View

       ↓

Get students ordered by points

       ↓

Prepare response

       ↓

Return response
```

A view can:

* Receive request data
* Validate information
* Query the database
* Perform business logic
* Call other application components
* Return a response

---

# 32. Template

A **Template** is used to generate the user-facing HTML.

For example:

```text

1. Arjun — 950 points
2. Ravi  — 820 points
3. Priya — 760 points
```

The template receives data and uses it to generate HTML.

Django's template language allows us to use:

* Variables
* Conditions
* Loops
* Template inheritance
* Filters
* Tags

For example:

```html
<h1>Welcome, {{ student.name }}</h1>
```

The actual value of `student.name` is supplied by the application.

# 45. Common Beginner Confusions

## Confusion 1: Is Django frontend or backend?

Django is primarily a **backend web framework**.

Django can also generate HTML using its template system, but its main role is server-side application development.

---

## Confusion 2: Is HTML Django?

No.

HTML is a markup language.

Django is a Python web framework.

They can work together:

```text
Django
   ↓
Django Template
   ↓
HTML
   ↓
Browser
```

---

## Confusion 3: Is a database the backend?

No.

A database is a separate data-storage system that the backend communicates with.

```text
Frontend
   ↓
Backend
   ↓
Database
```

---

## Confusion 4: Is Django a programming language?

No.

```text
Python = Programming Language

Django = Python Web Framework
```

---

## Confusion 5: Is Django the same as a database?

No.

Django can communicate with databases such as:

* SQLite
* PostgreSQL
* MySQL
* MariaDB

# 48. Day 1 Interview Questions

### Beginner Level

**1. What is Django?**

Django is a high-level Python web framework for building web applications.

**2. Is Django frontend or backend?**

Primarily backend/server-side.

**3. What is HTTP?**

HTTP is a protocol used for communication between clients and web servers.

**4. What is a client?**

A client is software that sends requests to a server.

**5. What is a server?**

A server receives requests, processes them, and returns responses.

**6. What is a database?**

A system used to persistently store and manage application data.

**7. What is an API?**

An interface that allows software systems to communicate.

**8. What does ORM stand for?**

Object-Relational Mapping.

**9. What does MVT stand for?**

Model, View, Template.

**10. What is a Django Model?**

A Python representation of application data that Django's ORM maps to database operations.

**11. What is a Django View?**

Code that receives a request and produces an appropriate response.

**12. What is a Django Template?**

A template used to generate HTML dynamically.

**13. What is the difference between a Django project and app?**

A project represents the overall Django application/configuration, while an app is a reusable component that provides a specific area of functionality.
