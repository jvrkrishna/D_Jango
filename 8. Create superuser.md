# 1️⃣ What is Migration in Django?

**Migration** is Django's way of applying changes from your Django models to the database structure.

Simple meaning:

> **Migration keeps the Django models and database structure synchronized.**

The basic flow is:

```text
Django Model
     ↓
Migration
     ↓
Database Table
```

---

# 🧠 Simple Example

Suppose we create a model:

```python
class Student(models.Model):

    name = models.CharField(max_length=100)

    age = models.IntegerField()
```

Django needs to create a corresponding table in the database.

Migration helps Django keep the database structure updated according to the model.

---

# 🎯 Two Important Migration Commands

There are two main commands:

```text
makemigrations
migrate
```

Remember them as:

```text
makemigrations
       ↓
Prepare the changes

migrate
       ↓
Apply the changes
```

---

# 2️⃣ `makemigrations`

## 📌 Command

```bash
python manage.py makemigrations
```

or:

```bash
py manage.py makemigrations
```

### Purpose

`makemigrations` creates migration files based on changes made to Django models.

Simple meaning:

> **`makemigrations` prepares the database changes.**

---

# 📌 Example

Run:

```bash
py manage.py makemigrations
```

You may see:

```text
No changes detected
```

This means:

> Django did not find any new model changes that require a migration file.

Example:

```text
PS C:\Users\...\Sample_Project> py manage.py makemigrations

No changes detected
```

---

# 3️⃣ `migrate`

## 📌 Command

```bash
python manage.py migrate
```

or:

```bash
py manage.py migrate
```

### Purpose

`migrate` applies pending migrations to the database.

Simple meaning:

> **`migrate` takes the prepared migration changes and applies them to the database.**

---

# 📊 `makemigrations` vs `migrate`

| Command | Purpose |
|---|---|
| `makemigrations` | Creates migration files |
| `migrate` | Applies migration files to the database |

Easy way to remember:

```text
makemigrations
      ↓
Prepare

migrate
      ↓
Apply
```

---

# 📌 Run Migration

Run:

```bash
py manage.py migrate
```

Django applies all pending migrations.

You may see migrations for built-in Django applications such as:

```text
admin
auth
contenttypes
sessions
```

These built-in applications need database tables for Django's features.

---

# 🧠 What Happens During `migrate`?

Conceptually:

```text
Migration Files
       ↓
py manage.py migrate
       ↓
Database
       ↓
Tables Created / Updated
```

Django's authentication system also uses database tables for users, groups, and permissions.

---

# 4️⃣ Django Authentication System

Django provides a built-in authentication system.

It manages:

```text
Users
Groups
Permissions
Authentication
```

The built-in authentication application is:

```text
django.contrib.auth
```

It is included in a normal Django project by default.

---

# 5️⃣ What Is a User?

A **User** represents a person who can authenticate with a Django application.

A user can have information such as:

```text
Username
Password
Email
Permissions
Groups
```

Django's authentication system manages these users.

---

# 6️⃣ What Is a Superuser?

A **Superuser** is a user with full permissions.

Simple meaning:

> **A superuser has all permissions and can access the Django Admin Panel.**

A superuser is commonly used by the developer or administrator to manage the website through Django Admin.

---

# 📊 User vs Superuser

| User | Superuser |
|---|---|
| Normal authenticated user | Administrator-level user |
| Permissions can be limited | Has all permissions |
| May not access all admin features | Can access Django Admin |
| Used for normal application functionality | Used for administration |

---

# 7️⃣ Create a Superuser

## 📌 Command

Run:

```bash
py manage.py createsuperuser
```

Django will ask for information such as:

```text
Username:
Email address:
Password:
Password (again):
```

---

# 📌 Example

```text
PS C:\Users\...\Sample_Project> py manage.py createsuperuser

Username: rk
Email address: rk@gmail.com
Password:
Password (again):
```

The password is normally not displayed while typing.

---

# ⚠️ Password Validation

Django checks the password against its password validation rules.

For example, Django may reject passwords that are:

```text
Too short
Too common
Entirely numeric
Too similar to user information
```

A development setup may allow you to continue after Django warns that the password does not meet its validation rules.

For real applications:

> **Always use a strong password.**

Do not use simple passwords such as:

```text
1234
password
12345678
```

---

# 📌 Successful Superuser Creation

After successful creation, Django displays a message similar to:

```text
Superuser created successfully.
```

Now the database contains the superuser account.

---

# 🧠 Superuser Creation Flow

```text
py manage.py createsuperuser
             ↓
       Enter username
             ↓
        Enter email
             ↓
       Enter password
             ↓
      Django validates
             ↓
       Superuser created
```
